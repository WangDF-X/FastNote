## 1. 目的与范围

定义小记页面的核心展示：列表布局、排序方式、分组（按日期）、快速删除与恢复机制。确保用户能够快速浏览和管理临时记录内容。

**范围内**: 列表渲染、排序与分页、清理操作、恢复提示。
**范围外**: 快速捕获窗口（NOTE-02）、小记转任务（NOTE-02）、系统通知提醒（REM-01）。

## 3. 页面布局

```text
小记
├── 共 N 条                         ← 页面头部副标题
├──                               ← 分隔线
├── [今日]                        ← 分组头（可按日期折叠）
│   • 标题行 1           10:23    ← 摘要 + 更新时间
│   • 标题行 2           09:15
│                                 
├── [昨天]
│   • 另一条笔记         18:45
│   
├── [10月18日]
│   ···
└── [+ 快速添加]                  ← 底部固定按钮
```

- 每个分组最多 20 条；超出后显示「查看更多」。
- 每条笔记显示：前 40 字符的正文摘要 + 更新时间（HH:mm）。
- 点击条目打开编辑模式。

---

## 4. 排序规则

| 排序依据 | 说明 |
| --- | --- |
| `updated_at DESC`（默认） | 最近修改的在最上面 |
| `created_at DESC` | 新创建的在最上面 |

设置中不提供排序切换入口（第一版固定为 updated_at DESC）。

> **已确认（2026-10-26）Q-NOTE-01：** 是否允许用户手动排序或固定置顶某些小记？→ **当前默认处理：** 不支持，仅按 updated_at 降序排列。v2 再评估 Pin/Manual Sort。

## 6. 清理操作

### 6.1 单次删除

点击条目右侧「⋮」菜单 → 「删除」 → 弹确认 Dialog → 永久删除。

### 6.2 清除全部

页面底部「清理全部」按钮 → 弹确认 Dialog「删除所有 N 条小记？」 → 确认后全部删除。

### 6.3 自动回收提示

如果用户在清理操作中误删了有重要内容的笔记，第一版不提供回收站。但在删除成功后 Toast 中增加一个可选操作「撤销」（2s 内有效），撤销后将该批次恢复。

> **已确认（2026-10-26）Q-NOTE-02：** 用户一次性清空全部小记后，是否提供全局级别的恢复？→ **当前默认处理：** 不实现全局恢复（无回收站）；仅在一次操作的撤销窗口内可恢复同批次删除的内容。Toast 中显示恢复选项并限制在 2s 内。

---

## 7. 保存策略

- 每次创建/修改小记后立即写入 SQLite。
- 文本编辑 500ms 防抖自动保存。
- 保存失败时 inline error + 页面级 Banner。
