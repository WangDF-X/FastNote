## 1. 目的与范围

定义日记页面的「回顾」功能：在编辑某日日记时，自动关联当天完成的任务（due_date == date OR status changed to Completed on that date），并提供任务摘要和跳转入口。确保用户能够通过日记回顾当天的工作进展。

**范围内**: 回顾面板、任务关联规则、摘要展示、任务跳转。
**范围外**: 日记的模板系统（v1 无）、多日记聚合分析（v1 无）。

## 3. 回顾面板

### 3.1 打开方式

在日记编辑器中，页面右侧（或下方）显示回顾面板。面板标题为「今日回顾」。

### 3.2 面板内容

```text
┌─────────────────────────────┐
│ 今日回顾                    │
├─────────────────────────────┤
│                             │
│ ✅ 已完成（3）              │
│ • 完成季度报告              │
│ • 提交设计稿                │
│ • 团队周会                  │
│                             │
│ ⏰ 到期（2）               │
│ • 修改 Bug #123             │
│ • 准备演示文稿              │
│                             │
│                             │
│       [关闭]                │
└─────────────────────────────┘
```

- 两个分组：**已完成**（状态变为 Completed 且日期为当天）和 **到期**（due_date == 当天）。
- 每个条目可点击 → 打开对应任务的详情面板。
- 总数标注在分组标题旁（如 `已完成（3）`）。

## 4. 任务关联规则

### 4.1 包含条件

| 分组 | 包含条件 |
| --- | --- |
| 已完成 | `status = Completed` 且 `(completed_at == today OR due_date == today)` |
| 到期 | `due_date == today` 且 `status != Completed` |

> **已确认（2026-10-26）Q-DIARY-04：** 回顾是否包含今天新建/开始的任务？→ **当前默认处理：** 不包含；只包含已完成（completed）和到期（due）的任务。避免列表过长干扰回顾。

### 4.2 数量限制

- 最多显示 50 条任务（按 created_at DESC 排序取前 50）。
- 超过 50 条时在底部显示「还有 N 项」（灰色小字，不可交互）。

> **已确认（2026-10-26）Q-DIARY-05：** 50 条的限制是否足够？→ **当前默认处理：** 足够 + 显示「还有N项」提示；不做翻页/加载更多。

### 4.3 归档计划任务

遵循 D-09：归档计划的任务在今日常规视图中隐藏，但在日记的历史回顾中仍然可见（保证记录完整性）。

## 5. 摘要格式

当用户在日记中引用某个任务时，任务名以可点击链接的形式呈现：

```markdown
今天完成了 [完成季度报告](task://taskId) 和 [提交设计稿](task://taskId)。
```

第一版不解析 Markdown——但 UI 层会在渲染时将符合特定格式的文本转换为可点击元素（正则匹配 `\[.*?\]\(task://.*?\)`）。

---

## 6. 总结展示

每日回顾结束时，顶部显示一行简短总结：

```text
📊 今日完成 3 项，到期 2 项 · 进度 60%
```

格式为单行文本，各部分用顿号分隔。

> **已确认（2026-10-26）Q-DIARY-06：** 汇总信息的展示格式是否为多行列表？→ **当前默认处理：** 使用单行格式，用顿号（`·`）分隔各部分信息（完成数、到期数、进度百分比）。
