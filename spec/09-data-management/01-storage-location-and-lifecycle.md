## 1. 目的与范围

定义 FastNote 数据存储位置的可见性、可修改性和存储空间管理。确保用户始终知道自己在哪里以及磁盘空间是否足够，并在空间不足时获得及时预警。

**范围内**: 数据库文件路径、app_meta 位置、存储空间显示与预警、目录创建。
**范围外**: 备份与恢复（DATA-02）、导入导出（DATA-03）。

## 3. 存储结构

```
{data_dir}/                          # 数据根目录（见 §4）
├── fastnote.db                      # SQLite 主数据库（WAL 模式）
│   ├── fastnote.db-wal              # WAL 日志
│   └── fastnote.db-shm              # Shared memory
├── app_meta.json                    # 应用元数据（设置、窗口几何、入口位置等）
└── backups/                         # 自动备份目录（DATA-02）
    └── backup_YYYYMMDD_HHMMSS.db.copy
```

### 3.1 文件权限

| 文件 | 权限 |
| --- | --- |
| `fastnote.db` | 用户可读可写；仅当前系统账户可访问 |
| `app_meta.json` | 同左 |
| `backups/` | 只由应用写入，用户可通过 UI 浏览和复制 |

## 4. 存储位置

| 平台 | 默认路径 |
| --- | --- |
| Windows | `%APPDATA%\FastNote\` |
| macOS | `$HOME/Library/Application Support/FastNote/` |
| Linux | `$XDG_CONFIG_HOME/fastnote/` 或 `$HOME/.config/fastnote/` |

- 用户在设置中可查看完整路径（等宽字体 + 可复制按钮）。
- **不可修改路径**（第一版不支持自定义存储位置），以简化数据一致性和迁移问题。

## 5. 存储容量预警

### 5.1 监测方式

应用每次启动时检查 data_dir 所在分区的可用空间：

| 条件 | 行为 |
| --- | --- |
| 可用空间 > 200MB | 无动作 |
| 可用空间 ≤ 200MB | 页面级 Banner「磁盘空间不足，修改可能无法保存」+ 详情（剩余 MB） |
| 可用空间 ≤ 50MB | 错误级别提示；创建备份失败时也阻止操作 |

> **已确认（2026-10-26）Q-DATA-01：** 是否需要手动触发完整性检查按钮？→ **当前默认处理：** 不实现——完整性检查在启动时自动执行且在后台进行，无需用户干预。

> **已确认（2026-10-26）Q-DATA-02：** 备份目录是否可以设在同步盘（如 OneDrive/Dropbox）中？→ **当前默认处理：** 允许但有 warning——如果检测到路径在同步盘中则 Toast「备份将在同步后写入云端，可能导致版本冲突」。

> **已确认（2026-10-26）Q-DATA-03：** >200MB 预警的通知强度？→ **当前默认处理：** 警告级文本 + 日志记录，不弹 Popup 对话框打断用户操作。

## 6. 数据目录生命周期

| 阶段 | 行为 |
| --- | --- |
| 首次启动 | 创建 data_dir + fastnote.db（初始化 schema）+ app_meta.json（写入默认值） |
| 日常运行 | DB 以 WAL 模式运行；meta JSON 防抖写入（5s 或事件驱动） |
| 退出 | checkpoint 写 DB；flush meta JSON |
| 重新安装 | 保留旧 data_dir 不被删除（用户可选择清除） |
