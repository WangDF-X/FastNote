## 1. 目的与范围

定义 FastNote 的数据导出为 JSON 格式和从 JSON 导入的完整流程。JSON 作为可阅读、可编辑、第三方工具可用的交换格式（而非主存储）。确保导出的数据结构稳定且导入时安全可控。

**范围内**: 导出内容、导出文件格式、导入模式、进度与回滚。
**范围外**: 备份/恢复（DATA-02）、加密、CSV/Markdown 导出。

## 3. 导出

### 3.1 导出内容

| 实体集合 | 说明 |
| --- | --- |
| `plans` | 所有计划（含归档） |
| `stages` | 所有阶段 |
| `tasks` | 所有任务（含已完成） |
| `notes` | 所有小记 |
| `journals` | 所有日记 |
| `settings` | 通用设置 + 任务偏好（不含路径相关字段） |
| `meta` | 应用元数据中不敏感的部分 |

> **已确认（2026-10-26）Q-DATA-21：** 导出是否包含 app_meta（如窗口几何、入口位置等）？→ **当前默认处理：** 不包含——app_meta 是环境相关的，重新安装后会自动生成合理默认值。

### 3.2 文件格式

```jsonc
{
  "format_version": 2,
  "exported_at": "2026-10-23T14:32:00Z",
  "fastnote_version": "1.0.0",
  "data": {
    "plans": [ ... ],
    "stages": [ ... ],
    "tasks": [ ... ],
    "notes": [ ... ],
    "journals": [ ... ],
    "settings": { ... }
  }
}
```

- `format_version = 2`（与 schema v2 对应）。
- 文件编码：UTF-8。
- 缩进：2 空格（可读性优先于体积）。
- 文件大小预期：典型使用场景 < 5MB。

### 3.3 导出流程

```text
1. 用户点击「导出数据」按钮 → 弹出文件选择对话框
2. 选择保存路径 → .json 后缀自动补全
3. 执行导出：
   a. 从 DB 读取所有实体
   b. 组装 JSON 对象
   c. 写入文件
4. Toast「已导出到 path.json」+ 「打开文件夹」链接
5. 同时记录日志：导出完成, count=N entities, size=M KB
```

导出期间：
- 显示模态进度框：「正在导出数据...」（不可取消或提供取消按钮）。
- 预计耗时：< 500ms（典型情况）。

## 4. 导入

### 4.1 导入前确认

点击「导入数据」→ 选择 `.json` 文件 → 弹窗预览并确认：

```text
┌───────────────────────────────────┐
│ 导入数据                          │
│                                   │
│ 文件: fastnote_export_2026.json   │
│ 版本: format_version=2            │
│                                   │
│ 导入内容:                         │
│ • 计划    3 个                    │
│ • 阶段    7 个                    │
│ • 任务   45 个                    │
│ • 小记   23 条                    │
│ • 日记   12 篇                    │
│                                   │
│ 导入模式: 替换现有数据             │
│ ──────────────────────           │
│ ⚠ 当前全部数据将被此文件中的内容替换。│
│    导入前会自动创建一次备份。      │
│                                   │
│         [取消]    [确认导入]      │
└───────────────────────────────────┘
```

### 4.2 导入模式

| 模式 | 行为 |
| --- | --- |
| 替换（唯一模式） | 清空当前数据库 → 按 ID 覆盖写入 → 提交事务 |
| （v2 考虑增量） | — |

> **设计决策 D-39：** 第一版仅支持「替换」模式——导入会完全替换当前数据库中的计划、任务、小记、日记和设置。不做「追加」「合并」模式以减少冲突处理的复杂度。

> **已确认（2026-10-26）Q-DATA-22：** 同名计划在替换模式下是否有 merge 选项？→ **当前默认处理：** 不支持 merge——只计数并列出条目数；用户需自行决定是否需要合并后再导入。

### 4.3 导入流程

```text
1. 读取并验证 JSON 结构（schema check）
2. 自动创建一次备份 → backup_pre_import_YYYYMMDD.db.copy
3. BEGIN IMMEDIATE 事务
4. 删除 plans/stages/tasks/notes/journals 中的所有数据
5. 逐批次 INSERT 新数据（每 100 条 commit 一次检查点）
6. COMMIT
7. Toast「已导入 N 个实体，正在重启...」
8. std::process::exit(0) → 下次启动加载新数据
```

### 4.4 错误处理

| 错误类型 | 处理方式 |
| --- | --- |
| JSON 格式错误 | Dialog 告知具体行号和错误原因 |
| schema version 不匹配 | Dialog 告知需要更新的版本 |
| 磁盘空间不足 | 中止导入 + 提示 + 自动删除了备份（如有） |
| 导入中途崩溃 | 下次启动时检测到异常标记 → 自动回滚到 pre-import 备份 |

### 4.5 导入进度

长任务线程以 `DataTaskProgress` 事件推送进度：

| 阶段 | 百分比 |
| --- | --- |
| 验证 | 0–20% |
| 备份创建 | 20–30% |
| 清理旧数据 | 30–35% |
| 写入新数据 | 35–95% |
| 校验完整性 | 95–100% |

## 5. 其他导出格式

| 格式 | 支持情况 | 说明 |
| --- | --- | --- |
| Markdown | 不支持（v1） | 未来可能作为打印/分享用途 |
| CSV | 不支持（v1） | 结构化数据但不支持嵌套关系 |

> **已确认（2026-10-26）Q-DATA-23：** 是否需要在 v1 中支持 Markdown 或 CSV 导出？→ **当前默认处理：** 不实现——JSON 是唯一受支持的导出格式。Markdown/CSV 在 v2 评估。
