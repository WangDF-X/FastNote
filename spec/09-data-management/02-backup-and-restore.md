## 1. 目的与范围

定义 FastNote 的自动备份和手动备份/恢复流程，确保用户的数据安全且可随时回滚到任意历史版本。备份采用完整文件复制方式（不增量），因为数据库体积小、单文件便于传输。

**范围内**: 自动备份策略、手动创建备份、恢复流程、备份列表管理。
**范围外**: 导入/导出 JSON（DATA-03）、加密备份。

## 3. 自动备份

### 3.1 触发时机

| 事件 | 行为 |
| --- | --- |
| 启动时检测到 DB 大小变化（上次退出后） | 自动创建一个时间戳命名的 `.db.copy` 到 `backups/` 目录 |
| 每次 schema 迁移后 | 自动备份当前版本 |

### 3.2 自动备份存储

- 位置：`{data_dir}/backups/backup_YYYYMMDD_HHMMSS.db.copy`
- 名称包含创建时间戳，保证唯一性。
- **最大保留数量**：最近 10 份；超出时 oldest-first 清理（最旧的先删除）。

> **已确认（2026-10-26）Q-DATA-11：** 是否自动清理用户自定义备份目录中的旧文件？→ **当前默认处理：** 不自动清理用户目录——仅对应用管理的 `backups/` 自动保留最近 10 份；用户在设置中指定的外部备份目录由用户自己管理。

### 3.3 备份校验

备份完成后立即读取文件大小并与源文件对比：如果不一致则标记为失败并从 backups 中移除。不计算 SHA-256 哈希（性能考虑）。

## 4. 手动创建备份

在设置中心「备份与恢复」子页面点击「创建备份」按钮：

```text
┌───────────────────────────────────┐
│ 创建备份                          │
│                                   │
│ 目标路径: {data_dir}/...          │
│ 预估大小: 1.2 MB                  │
│                                   │
│         [取消]    [确定]          │
└───────────────────────────────────┘
```

- 文件名格式同自动备份：`backup_YYYYMMDD_HHMMSS_user.db.copy`
- 执行期间显示进度条（准备 → 复制 → 校验 → 完成）。
- 成功后 Toast「备份已创建」+ 「查看」链接打开备份目录。

## 5. 恢复流程

### 5.1 入口

设置中心「备份与恢复」子页面中列出所有可用的备份文件（按时间倒序排列）。

### 5.2 选择与确认

点击某备份文件的「恢复」按钮 → Dialog 确认：

```text
┌───────────────────────────────────┐
│ 从备份恢复？                      │
│                                   │
│ 文件: backup_20261022.db.copy     │
│ 日期: 2026-10-22 14:32           │
│ 大小: 1.2 MB                      │
│                                   │
│ 注意：当前数据将被备份后替换。     │
│       应用需要重启。               │
│                                   │
│         [取消]    [恢复并重启]    │
└───────────────────────────────────┘
```

### 5.3 执行步骤

```text
1. 将当前 fastnote.db → fastnote.db.pre-restore.YYYYMMDD_HHMMSS
2. 将备份文件复制到 fastnote.db
3. 运行 integrity_check 验证
4. Toast 提示正在重启...
5. std::process::exit(0)
6. 下次启动加载新 DB + checkpoint
```

> **已确认（2026-10-26）Q-DATA-12：** 恢复操作是否需要显示详细的结果摘要页面？→ **当前默认处理：** 不需要——恢复成功仅 Toast 告知「已从 X 备份恢复，正在重启」；失败时在当前页显示错误详情。

> **已确认（2026-10-26）Q-DATA-13：** 备份文件是否附带 SHA-256 哈希值用于完整性校验？→ **当前默认处理：** 不使用哈希——依赖 `integrity_check` SQL 命令进行校验，避免额外的存储和性能开销。

## 6. 备份列表管理

| 列 | 内容 |
| --- | --- |
| 文件名 | `backup_YYYYMMDD_HHMMSS.db.copy` |
| 大小 | `1.2 MB` |
| 类型 | 自动 / 手动 |
| 操作 | 「恢复」「删除」 |

- 同时最多显示 50 个备份条目；超过时使用虚拟列表或分页。
- 「全部清理」按钮（危险操作）→ 二次确认 → 清除所有自动备份（手动标记的不受影响）。
