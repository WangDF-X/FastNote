## 1. 目的与范围

定义 FastNote 默认常驻入口——悬浮球的完整行为规范：创建与渲染、鼠标交互（左键/右键）、拖拽移动、屏幕感知、关闭方式、平台差异与失败降级策略，确保用户在任何三平台上都能通过一致的悬浮球快速打开主界面。

**范围内**: 窗口属性、渲染模式、点击行为、拖拽、右键菜单、显示/隐藏触发时机、位置存储、平台降级。
**范围外**: 全局快捷键（ENTRY-03）、托盘行为（ENTRY-02）、悬浮球尺寸调节（SET-02）。

> **本轮 Windows 范围（2026-11-03 更新确认）：** 以 SHELL-01 §5.4 与上游 ARCH-04/06 为准，接入双入口最小闭环、已有品牌图标、拖动和位置持久化。深色模式增量按 SET-02 §3.2 同步球体与自绘入口菜单；球体图标按实际主题使用已有彩色/反色资源，不重新生成资产。下文的跨平台、首次高亮、低电量与额外动效仍不在本轮，不宣称相关 AC 已通过。

## 3. 基本规范

### 3.1 窗口属性

| 项 | 值 |
| --- | --- |
| 尺寸 | 默认 48 × 48 球体和透明工具窗口，无额外留白；后续设置范围按 ARCH-04 的 48–96 |
| 形状 | 固定圆形（超出部分 clip）；内容区居中对齐 |
| 背景 | 半透明填充（`bg.canvas` + `opacity`），圆角 = 半径（完全圆形） |
| 图标 | Slint Image，居中；Windows v1 浅色使用现有小尺寸彩色 SVG，深色使用现有反色 SVG，不手工重新着色 |
| 层级 | AlwaysOnTop / LevelAboveNormal；始终浮于普通窗口之上，但允许被全屏窗口覆盖 |
| 交互 | ClickThrough 可选（设置项），默认不穿透（所有事件正常接收） |
| 动画 | 无持续动画；出现时 fade-in 200ms，消失时 fade-out 150ms |

### 3.2 渲染模式

| 平台 | 实现方式 | 说明 |
| --- | --- | --- |
| Windows | `Window::set_frameless(true)` + 自定义标题栏隐藏 + `SetWindowPos(SWP_NOACTIVATE)` | 透明层使用 DWM 扩展；Logo 使用 `ImageBrush` |
| macOS | `NSPanel` + `ignoresMouseEvents=YES` + `occlusionStateEnabled=NO` | 非激活时仍可见；通过 `level=FloatingLevel` 置顶 |
| Linux(X11) | `setTransientForHint` + `_NET_WM_WINDOW_TYPE_DOCK` + TransparentBackground | xdotool/compiz 兼容；XRender alpha 合成 |
| Linux(Wayland) | WLR/XDG 顶级弹出协议，尽量模拟悬浮效果 | 能力探测后可能降级为不显示或 Toast 告知 |

### 3.3 图标与颜色适配

- Windows v1 Logo 按 SET-02 的实际主题（包括手动主题）切换现有彩色/反色 SVG；球体背景、边框与菜单文字同步，不改写图标资产。
- 不跟随操作系统 accent color（区别于 macOS Dock icon）。
- 焦点态：实际键盘操作保持，获取焦点时不额外描边；自绘入口菜单保留当前项的淡色背景，不绘制蓝色焦点框（ARCH-05 D-TODAY-07，2026-11-03 用户要求）。

## 4. 鼠标交互

### 4.1 左键点击

| 场景 | 行为 |
| --- | --- |
| 主窗口未打开 | 先隐藏球，再打开主窗口并导航到 `Today`；记录来源为 `BallLeftClick` |
| 主窗口已打开且可见 | 球不显示；重复/延迟事件不创建重复窗口 |
| 主窗口已打开但隐藏（hide 而非 quit） | 先隐藏球，再显示主窗口并恢复上次路由 |
| 按住移动超过 4px | 进入拖拽模式；松开后停止（不计为点击），不要求长按 |

### 4.2 右键点击

打开上下文菜单（Popup Menu），选项固定如下：

| 菜单项 | 行为 | 快捷键指示 |
| --- | --- | --- |
| 今日任务 | 切换到 Today 并显示主窗口 | — |
| 日历 | 切换到 Calendar 并显示主窗口 | — |
| 小记 | 切换到 Notes 并显示主窗口 | — |
| 日记 | 切换到 Journal 并显示主窗口 | — |
| 计划板 | 切换到 PlanList 并显示主窗口 | — |
| —— | 分隔线 | — |
| 设置 | 切换到 Settings 并显示主窗口 | — |
| 退出 | 执行退出流程（冲刷文本、注销热键等） | — |

- 菜单位置：以鼠标指针为中心弹出，最多一层子菜单（无嵌套）。
- 点击菜单项后菜单立即关闭；如果选中「退出」则走完整退出流程。
- 点击菜单以外的任何地方，菜单收起但不触发其他动作。
- 悬浮球被键盘焦点捕获时（无障碍场景），按 `Enter`/`Space` 等同于左键，`Alt+Enter` 等同于右键。

## 5. 拖拽与定位

### 5.1 拖拽

- **启动条件**：左键按下后移动超过 4px（ARCH-06 §5.2）；中键无操作。
- **移动过程**：窗口跟随光标实时移动；不产生重绘闪烁（使用原生 WM 移动协议）。
- **松手位置记录**：结束拖拽后写入 `appearance.ball_position {x,y,monitor}` 到 SQLite `app_settings`（ARCH-04）。
- **边界约束**：移动过程中若超出显示器区域，回到最近的有效边界（不在无效区域停留）。

### 5.2 屏幕感知与碰撞检测

| 场景 | 行为 |
| --- | --- |
| 靠近另一窗口 <20px | 吸附对齐并停在该位置（边缘对齐），类似 macOS Launchpad 磁贴 |
| 拖拽经过全屏窗口 | 不可见/跳过；该全屏窗口关闭后再检查吸附 |
| 多显示器拉伸 | 保持原有相对位置比例；跨屏时校验目标显示器是否存在 |
| 回到默认位 | 设置页提供「重置位置」按钮（右侧箭头图标） |

### 5.3 主屏默认位置

首次需要显示球或重置位置时：主显示器工作区右下角，球体紧贴右侧和底部，不覆盖任务栏。拖动松手与恢复旧位置后只贴最近的左/右工作区边缘；左右等距时左侧优先，纵向保留高度，仅越界夹取，不吸附上下边（ARCH-06 §5.1–5.2、Q-SHELL-07）。

## 6. 平台差异

### 6.1 Windows

- 无边框 + 圆角矩形 clip（Slint 不支持直接圆形，用 `clip_path` 实现圆形遮罩）。
- DWM 启用 rounded corner 扩展；任务栏不显示悬浮球。
- `SetLayeredWindowAttributes` 实现 alpha 混合。

### 6.2 macOS

- 使用 `NSPanel`（非 `NSWindow`），配置 `styleMask=` 去除装饰元素。
- `ignoresMouseEvents` 在非操作模式下保持透明（不影响性能，macOS 原生优化）。
- 右键菜单使用 `NSMenu`；Dock 上无图标（`LSUIElement=true`）。

### 6.3 Linux

- **X11**：使用 `_NET_WM_WINDOW_TYPE_DOCK` + `_NET_WM_STRUT_PARTIAL`，使窗口不被普通 WM 管理，同时不被面板遮挡。
- **Wayland**：WLR/XDG 顶级弹出层不支持 always-on-top；需要 compositor 协作。检测到 Wayland 后仍然尝试创建窗口（fallback），但通过 Toast 明确告知用户当前环境不支持完整悬浮球功能，建议临时使用托盘模式。
- **Gnome Shell**：GNOME 的 dock/panel 可能覆盖此类窗口；通过通知建议调整。

## 7. 生命周期与降级

### 7.1 创建流程

```text
1. 读取设置 entry_mode == ball → 是 → 继续
2. 检测平台能力：Windows/macOS 通过；Linux → 检查 X11/Wayland
3. 创建无边框窗口，加载 Logo Image，设置 alpha/layer
4. 注册鼠标事件：press + move(超过4px→drag), click, right_click
5. 校验工作区位置 → 仅在主窗隐藏时显示，主窗可见时不显示球（本轮无 fade 动画）
```

### 7.2 失败降级

| 失败原因 | 降级行为 |
| --- | --- |
| 平台 API 不支持创建透明置顶窗口 | Toast 告知 + 临时使用 tray（如有支持），不静默改写用户配置 |
| X11 可用但 Wayland 下失败 | 仍然创建窗口但不保证 always-on-top；Toast 告知 |
| 所有入口均失败 | 只显示主窗口，不创建任何常驻入口 |
| 用户手动关闭悬浮球后重启 | 重新创建，恢复到上次位置和状态 |

### 7.3 隐藏与销毁

- 用户不主动"关闭"悬浮球；唯一销毁方式是切换到 `tray` 模式或退出应用。
- 主窗口与球互斥：打开/恢复主窗先隐藏球；球模式系统最小化或按关闭策略隐藏主窗后显示球。主窗从任务栏移除，路由与几何保留。
- 手动启动只显示主窗；`--hidden` 才只显示球。切换失败清理目标并恢复原呈现；球创建失败时恢复主窗并提示。
- 应用进入后台休眠时暂停重绘（`AppEvent::EntryStateChanged{visible=false}`）。
- 切换入口模式：先销毁旧球再创建新入口（托盘或反之），不并行存在。

**D-RES-01（2026-11-04 已确认）：** 球模式的冷驻留不预建主窗/业务列表；主窗保存确认后隐藏，低成本资源最多热缓存 120 秒，球拖动/悬停/右键菜单不延长期限。到期或超预算回收主窗不销毁球/必要服务，也不重置应用路由与轻量会话。下次左键可冷重建原路由；真正资源释放及草稿保护沿用 [ENTRY-02 §7](02-tray-and-lifecycle.md) / [ARCH-01 §5](../00-architecture/01-tech-and-runtime.md)，不是把主窗永久隐藏在后台。

## 8. 特殊状态

### 8.1 首次启动高亮

启动并完成悬浮球创建后，窗口边框描边高亮 1 次（200ms `accent` 颜色），然后恢复正常外观。后续不再重复。

### 8.2 低电量模式

检测到系统低电量时（platform battery API ≤20%）：降低 opacity 到 0.6，减少重绘频率至每秒 1 帧。恢复时恢复正常。

### 8.3 隐私保护模式

未来预留（v1 不实现）：用户可在设置中一键隐藏/显示悬浮球而不改变入口模式。

## 9. 与设置的关联

- 悬浮球尺寸、透明度、默认位置由 [SET-02](../08-settings/02-general-and-appearance.md) §3 管理。
- `entry_mode` 开关位于 SET-02 §3.1，切换后立即生效（销毁旧入口 → 创建新入口）。
- `appearance.ball_opacity`、`appearance.ball_size`、`appearance.ball_position` 存于 SQLite `app_settings`；本轮只接入位置，尺寸/闲置透明度调节留给设置模块。

## 11. 设计决策与待确认

> **设计决策 D-30：** 悬浮球默认使用应用 Logo 而非纯颜色圆点。理由：品牌识别度高（用户能在复杂桌面环境中快速找到它），SVG 矢量缩放无损，且资源开销极小。

> **已确认（2026-10-26）Q-ENTRY-01：** Wayland 下若 compositor 不允许始终置顶窗口，是否仍创建悬浮球？→ **当前默认处理：** 仍然创建（尽力而为），同时通过 Toast 告知用户功能受限；允许用户保留设置不变以避免反复切换。

> **已确认（2026-10-26）Q-ENTRY-02：** 悬浮球位置在多显示器环境下从 A 屏拖到 B 屏后拔掉 B 屏，如何恢复？→ **当前默认处理：** 恢复到主屏幕右下角默认位，并 Toast 告知位置已校正。

> **已确认（2026-10-26）Q-ENTRY-03：** 悬浮球在全屏应用下是否自动隐藏？→ **当前默认处理：** 不自动隐藏（避免误判和频繁显隐造成干扰），用户可手动拖开或使用 Alt-tab 切换。
