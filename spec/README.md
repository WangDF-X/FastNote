## 1. 文档定位

本目录是 FastNote 第一版的**研发级设计规格**，用于把 [product.md](../product.md) 中的产品需求拆解为可开发、可测试、可验收的模块设计。它是后续开发、评审、测试与变更控制的依据文档，而不是产品宣传材料。

**本版覆盖范围**

- 功能模块划分、边界与相互依赖。
- 每个模块的页面结构、交互流程、状态与异常。
- 支撑开发所需的领域模型、数据表、接口契约与关键规则。
- 可测试的验收标准与产品需求追溯关系。

**本版不包含**（按约定留到后续轮次）

- 具体 Slint 组件树、`.slint` 文件组织与逐控件属性。
- 完整 Rust 模块内函数级实现、关键算法伪代码。
- 最终视觉稿/高保真设计稿。
- 具体排期与人力估算。

> **文档深度决策 D-04：** 本轮先交付研发级文档；待评审确认后，再针对复杂模块补充「详尽级」文档（DDL 落地细节、Slint 组件树、算法伪代码、页面线框），避免在需求尚未稳定时过度设计。

**模块划分原则**

1. **按用户可感知的功能域划分**，而不是按代码分层。每个模块一个文件夹，内部按「总览 → 子能力」拆分文档。
2. **跨模块能力集中定义一次**：统一任务模型在 `00-architecture/03`，任务详情面板在 `03-today-tasks/03`，反馈与弹窗规范在 `01-app-shell/02`，配置项在 `00-architecture/04`。其他文档只引用、不重复定义。
3. **常驻入口与主界面是同一产品的两种访问方式**（product §1.5），因此入口模块只描述入口行为，不复制业务功能。

### 2.2 命名与语言

- 目录名、文件名使用英文小写短横线（工具链友好、跨平台安全）。
- 文档正文使用简体中文；代码标识符、表名、枚举值、配置键使用英文。
- 日期一律 `YYYY-MM-DD`；时间戳一律 RFC 3339（存储 UTC，界面显示本地时间）。
- 文档间引用使用相对路径链接，便于在仓库内直接跳转。

## 4. 文档规范

### 4.1 每份文档的推荐结构

```text
# <编号> <标题>
> 文档编号 ｜ 模块 ｜ 状态 ｜ 更新日期
> 上游依赖 / 下游引用

## 1. 目的与范围
## 2. 需求追溯            （引用 product.md 章节与模块需求编号）
## 3. 设计与规则          （页面、流程、交互、状态、数据规则）
## 4. 数据与接口          （字段、DTO、服务方法、事件）
## 5. 边界、异常与提示    （空态、错误、冲突、极端场景）
## 6. 平台差异            （如适用）
## 7. 验收标准            （AC-xxx，可测试）
## 8. 设计决策与待确认    （D-xx / Q-xx）
```

模块总览文档可合并部分章节；子能力文档必须包含「规则」「异常」「验收」。

### 4.2 编号约定

| 前缀 | 含义 | 示例 |
| --- | --- | --- |
| `D-xx` | 已确定的设计决策 | `D-08` |
| `Q-xx` | 全局待确认问题（汇总于 QA-02） | `Q-03` |
| `Q-<模块>-xx` | 模块局部待确认问题（QA-02 汇总索引） | `Q-PLAN-01` |
| `D-<模块>-xx` | 模块局部设计决策 | `D-TODAY-01` |
| `INV-xx` | 领域不变量 | `INV-05` |
| `VAL-xx` | 输入/业务校验 | `VAL-07` |
| `E-xxx` | 错误码 | `E_DATE_RANGE` |
| `AC-<模块>-xx` | 验收标准 | `AC-TODAY-03` |
| `ARCH/SHELL/ENTRY/TODAY/CAL/NOTE/DIARY/PLAN/SET/DATA/QA` | 模块需求编号前缀 | `PLAN-014` |

### 4.3 用语

- **必须**：不可协商，未满足即缺陷。
- **应当**：默认要求，偏离需在评审中说明理由。
- **可以**：可选能力，不作为第一版验收项。
- **系统**：FastNote 应用本身；**用户**：使用产品的人。

### 4.4 决策标记

```markdown
> **设计决策 D-xx：** 结论 + 理由 + 影响范围。
> **已确认（2026-10-26）Q-xx：** 问题 + 候选方案 + 当前默认处理。
```

未决问题必须有「当前默认处理」，保证开发不被阻塞。

## 5. 术语表

| 术语 | 定义 |
| --- | --- |
| 常驻入口 | 悬浮球或系统托盘图标，用于快速打开主界面/快捷菜单。 |
| 悬浮球 | 可拖动、半透明、置顶的小窗口入口，默认常驻形式。 |
| 主界面 | 包含今日任务、日历、小记、日记、计划板的单窗口应用界面。 |
| 冷驻留 | 仅入口和必要后台服务运行，主窗/业务页已卸载；仅保留有界轻量会话/缓存。 |
| 热驻留 | 主窗隐藏成功后的低成本资源暂存，最长 120 秒；重资源优先回收，超预算或内存压力可提前结束。 |
| 分级加载/回收 | 打开界面才创建所需对象/查询；按对象成本和生命周期驱逐，不以隐藏或 Release 构建代替实际卸载。 |
| 计划（Plan） | 一个可并行管理的大型目标，包含阶段、任务与日期范围。 |
| 阶段（Stage） | 计划根下的分组节点，用于路线图展示；不参与任务状态统计，只有进度。 |
| 任务（Task） | 最小执行单元，可独立存在，也可归属计划/阶段/父任务。 |
| 子任务 | `parent_id` 指向另一任务的节点，层级不限。 |
| 待安排区域 | `status=todo` 且 `start_date` 与 `due_date` 均为空；无日期的进行中进入当前关注。 |
| 逾期任务 | 未完成且未归档的任务，已超过本地到期日期时间；旧全天任务仍为 `due_date < 今天`（D-TODAY-02）。 |
| 当前关注 / 稍后 | 工作关注区域，不是执行状态；条件及顺序以 ARCH-03 §8.2 为准。 |
| 阻塞 | 任务存在未完成的前置依赖；仅提示，不锁定。 |
| 小记（Note） | 快速记录的短文，可转换为任务。 |
| 日记（Journal） | 按自然日一篇的个人记录，可结合当日任务回顾。 |
| 今日 | 设备本地时区的自然日 `00:00–24:00`。 |
| 归档计划 | 已结束、只读、保留历史但不进入今日/日历的计划。 |

## 6. 已确定的关键决策

| 编号 | 决策 | 说明 |
| --- | --- | --- |
| D-01 | 三平台同步支持 | Windows 10+、macOS 12+、Linux（X11 完整支持，Wayland 尽力支持）。平台差异见 ARCH-06。 |
| D-02 | SQLite（rusqlite + WAL） | 本地单文件、事务安全、便于备份；不使用 JSON 作为主存储。 |
| D-03 | 统一任务树 | 阶段与任务同表存储，`kind` 区分；任务层级不限。 |
| D-04 | 本轮研发级文档 | 详尽级（组件树/DDL 落地/算法）后续轮次补充。 |
| D-05 | 中文正文 + 英文标识 | 目录/文件名英文，界面文案简体中文。 |
| D-06 | 纯本地、无网络 | 第一版不联网、不采集数据、不做云同步；为未来 Agent 预留本地只读接口边界。 |
| D-07 | 三种任务状态 | 未开始 / 进行中 / 已完成；状态与日期独立。D-TODAY-09（2026-11-08）删除等待中，旧值迁移为未开始。 |
| D-08 | 阶段无执行状态 | 阶段只有进度（由其下任务叶子计算），避免「阶段已完成但任务未完成」的矛盾。 |
| D-09 | 归档计划默认隐藏 | 归档计划的任务不出现在今日/日历；日记的历史回顾仍包含，保证记录完整。 |
| D-10 | 任务详情面板全局复用 | 今日、日历、计划板共用同一详情面板与校验规则（TODAY-03）。 |
| D-11 | 硬删除 + 明确确认 | 第一版不做回收站；计划必须先归档才能删除；删除阶段默认把任务移到计划根。 |
| D-12 | 每天一篇日记 | 以本地日期唯一；首次输入时创建，空内容不落库。 |
| D-13 | 小记转任务一对一 | 一条小记最多关联一个任务；可解除关联，原小记始终保留。 |
| D-14 | 默认悬浮球入口 | 首次启动显示主界面并创建悬浮球；后续手动启动显示主界面，开机自启只显示入口。 |
| D-15 | 第一版范围收敛 | 不含全局搜索、回收站、自动排期、甘特图、云同步、MCP/LLM、富文本。 |
| D-16 | 关键操作即时生效 | 无「保存」按钮；任务/设置改动立即持久化，文本编辑 500ms 防抖自动保存。 |
| D-17 | 系统只提示、不擅自改期 | 日期冲突、依赖未满足、进度异常均以提示呈现，不自动修改用户安排。 |
| D-18 | 不引入 async runtime | UI 线程 + DB 工作线程 + 通道足够；降低常驻内存与复杂度（ARCH-01）。 |
| D-19 | 命令/查询用枚举 | 显式跨线程边界，便于未来 Agent 复用同一命令层（ARCH-02）。 |
| D-20 | 父节点树 + `plan_id` 冗余 | 不用闭包表；移动时事务内维护整棵子树（ARCH-03）。 |
| D-21 | 三平台功能一致优先 | 入口形态允许遵循平台习惯，业务与数据一致（ARCH-06）。 |
| D-22 | Wayland 不实现 Portal 全局快捷键 | 能力探测为不支持，禁用并说明，不建议半可用（ARCH-06）。 |
| D-23 | 任务详情为非模态抽屉 | 可边看列表边编辑，不引入模态焦点栈（SHELL-01）。 |
| D-24 | 不做首次启动向导 | 打开即用；靠空态与设置引导（SHELL-01）。 |
| D-25 | 硬删除 + 强确认 | 第一版无回收站；破坏性操作必须明确确认（SHELL-02）。 |
| D-26 | 月/周日历 + 日期详情 | 用户 2026-10-25 确认；Today 独立，点击日期查看详情不算新增日视图，不做小时网格。 |
| D-27 | v1 系统通知 | 任务和小记均可设置单次、每天、每周提醒；无需小记转任务。 |
| D-28 | 仅运行时调度 | 隐藏驻留继续提醒，完全退出不提醒；启动/唤醒汇总补发最近 24 小时错过项，更早记已错过。 |
| D-29 | 提醒数据与排期分离 | 提醒模块在 schema v2 增加独立规则与账本，JSON format_version=2（兼容读 v1）；提醒不隐式修改任务排期或 Today 分组。 |
| D-TODAY-02 | 日期时间选择与行编辑 | 用户 2026-11-03 确认：开始/到期用选择组件设置分钟精度时间，按具体时分逾期；状态下拉与优先级在任务行，点击详情外部保存后关闭。schema v3 保留旧全天任务。 |
| D-RES-01 | 低内存常驻优先与两分钟热缓存 | 用户 2026-11-04 确认：按需创建主窗/页面，常用低成本资源有界保留，重资源优先回收；主窗热缓存最多 120 秒，可超预算提前结束。冷驻留 ≤80MB、热驻留/主窗活动态 ≤130MB，Release 实测；保护草稿与必要后台提醒。规格已确认，实现/资源验收待完成。 |

## 8. 全局约束摘要

- **性能**：Release 冷启动 ≤1.0s，冷驻留 ≤80MB，热驻留/主窗活动态 ≤130MB，空闲 CPU <0.5%，列表滚动 60fps（详见 ARCH-01 §5 与 QA-03 §8）。
- **生命周期**：隐藏启动不预建主窗/业务页；低成本资源白名单有界保留，主窗热缓存最长 120 秒，重资源先回收、超预算可提前结束。页面隐藏只失效不查询，草稿和必要后台服务不因回收丢失（D-RES-01）。
- **安全**：数据仅存本地；无网络请求；日志不记录任务/日记正文。
- **一致性**：数据库是唯一事实来源；任何模块的修改通过统一服务层落库并广播变更，不允许页面各自缓存可变副本。
- **可逆性**：破坏性操作必须二次确认；备份/恢复必须可在 UI 内完成。
- **可访问性**：全部核心操作可键盘完成；焦点可见；文本对比度满足 WCAG AA。
- **平台**：功能在三平台行为一致，允许入口形态与系统集成方式存在平台差异（ARCH-06）。
