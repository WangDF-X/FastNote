## 1. 目的与范围

定义「今日任务」页面的核心展示逻辑与分组规则：标题、日期显示、分组列表（逾期 / 今日到期 / 明天 / 未安排）、快速添加栏，以及滚动行为与视觉层级。确保用户在打开主窗时第一时间看到当天最重要的任务集合。

**范围内**: 页面布局、分组定义与排序、快速添加、滚动策略。
**范围外**: 任务操作（TODAY-02）、详情面板（TODAY-03）。

## 3. 页面结构

```text
今日任务
├── 页面头部（标题 + 日期 + 快速添加）
│   ├── 今日任务         （20/semibold）
│   └── 10月23日 周四     （12/secondary）
├── 快速添加行            （输入框 + Enter 保存，固定在最顶部）
├── 分组列表（按顺序渲染）
│   ├── ⚠ 逾期        （红色徽标计数）
│   ├── 📅 今日到期    （蓝色徽标计数）
│   ├── 📆 明天       （绿色徽标计数）
│   └── ☐ 未安排      （灰色，无徽标）
└── 空态提示（如无数据）
```

- 内容区独立滚动；头部吸顶不动；分组头（section header）吸顶于头部下方。
- 快速添加行在滚动时也固定在分组列表的顶部。

## 4. 分组规则

### 4.1 逾期（Overdue）

包含所有满足以下条件的任务：
- `due_date < today`（本地日期）且
- `status != Completed`

> **设计决策 D-32：** 只有设置了 `due_date` 的任务才可能进入逾期组；纯靠 `start_date` 的任务即使今天开始也不会被标记为逾期。

### 4.2 今日到期（Due Today）

包含 `due_date == today` 且 `status != Completed` 的任务。

### 4.3 明天（Tomorrow）

包含 `start_date == tomorrow` 或（`due_date == tomorrow` 且 `start_date <= tomorrow`）且 `status != Completed` 的任务。

> **设计决策 D-33：** 「明天」的定义始终基于自然日的下一天（本地时间），不受周末/节假日影响。

### 4.4 未安排（Unscheduled）

包含同时满足以下条件的任务：
- `start_date IS NULL AND due_date IS NULL`
- `status != Completed`

不包含：
- 已完成的任务（无论日期如何均不显示）
- 属于归档计划的任务（D-09）
- `parent_id IS NOT NULL` 但父任务不在当前查询结果中的子任务（子任务随父任务一起显示）

### 4.5 完成的任务去哪了？

**第一版不在今日页中展示已完成的任务**。已完成的任务仅出现在日记回顾（DIARY-02）和搜索/历史（未来功能）中。如果用户需要在 Today 查看历史完成项，暂不支持。

## 5. 排序与呈现

### 5.1 默认排序

在同组内，任务按以下优先级排序：
1. `priority DESC`（高 → 低）
2. `created_at DESC`（新创建在前）

> **已确认（2026-10-26）Q-TODAY-01：** 页面头部是否显示「明日任务数」预告（如右上角徽标）？→ **当前默认处理：** 不显示，避免信息过载。明日数量仅在各分组徽标中可见。

> **已确认（2026-10-26）Q-TODAY-02：** 「明天」分组在非周五的周末日（周六/周日）是否会包含下周一的任务？→ **当前默认处理：** 不会。「明天」严格按自然日计算，即周日之后明天是周一，而非跳过周末。

### 5.2 自定义排序

根据设置 `general.default_sort` 调整同组内的排序方式：

| sort 值 | 排序依据 |
| --- | --- |
| `priority_desc_created_asc`（默认） | priority DESC, created ASC |
| `created_desc` | created_at DESC |
| `due_date_asc` | due_date ASC（NULL 排后） |

### 5.3 显示上限

每个分组最多显示 200 条任务；超出时底部显示「显示更多 X 项」（可点击展开至上限 1000）。

> **已确认（2026-10-26）Q-TODAY-03：** 单个分组成员超过 200 时如何处理？→ **当前默认处理：** 显示「显示更多」按钮，点击后加载剩余项（每次追加 200），最多加载 1000 项。不采用虚拟列表（简化开发）。

## 6. 隐藏组的恢复

当某个分组全部为空时，该分组从列表中**不隐藏也不折叠**——直接不渲染该分组头及分隔线。但如果用户通过新建任务产生了一个非空分组，则只渲染该新增任务所属的分组长。

> **已确认（2026-10-26）Q-TODAY-04：** 如果某分组被折叠后清空，再次新建任务时该分组是否自动展开？→ **当前默认处理：** 是的，但该行为仅限于新建任务的操作触发的场景；刷新事件不触发自动展开。

## 7. 窗口宽度适配

| 条件 | 行为 |
| --- | --- |
| 标准宽度（≤1280） | 列表最大宽度 1200px，居中 |
| 宽屏（>1280 且 ≤1600） | 使用全宽列表，两侧留白由页面头部控制 |
| 超宽屏（>1600） | 列表保持 1200 最大宽度；详情面板仍为 400px 固定 |

> **已确认（2026-10-26）Q-TODAY-05：** 超宽屏（>1600px）时今日页面列表是否撑满全宽？→ **当前默认处理：** 保持最大宽度 1200px 不变，避免超大屏幕上可读性降低。
