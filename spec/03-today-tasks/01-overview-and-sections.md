## 3. 页面结构

```text
今日任务
├── 统计区（未完成 / 逾期 / 今日完成；无公共模块标题条）
├── 快速添加行            （输入框 + Enter 保存，固定在最顶部）
├── 分组列表（按顺序渲染）
│   ├── 当前关注       （逾期置顶）
│   ├── 待安排
│   ├── 今日完成       （默认折叠）
│   └── 稍后           （默认折叠）
└── 空态提示（如无数据）
```

- 内容区独立滚动；快速添加固定，空态不能遮住快速添加。D-SHELL-02 将本地今日日期与星期迁至侧栏，移除 64px 公共标题条，不改变统计、分组或输入行为。
- 顶部展示「当前未完成」、逾期数、今日完成数；未完成统计包含启用区域的完整条目，不受折叠/分页影响，不新增稍后数量预告。
- 分组头包含名称、完整数量和折叠入口；折叠与每组加载数量在会话内保留。

## 4. 分组规则

归档计划与阶段节点先排除；每个任务只进入第一个命中的分组，不能因为隐藏分组而落入后面的分组。

| 顺序 | 分组 | 条件（未完成项按顺序去重） |
| --- | --- | --- |
| 1 | 当前关注 | 未完成，且逾期、开始日期不晚于今天、到期日期不晚于今天或状态为进行中 |
| 2 | 待安排 | `todo` 且开始/到期均为空 |
| 3 | 今日完成 | `done` 且完成时间换算为本地日期后等于今天 |
| 4 | 稍后 | 剩余未完成任务，已设置日期且所有已设置日期均晚于今天 |

- 稍后包含明天及更远的未来，不跳过周末、不仅限定下一天；所有有效未完成任务均进入当前关注、待安排或稍后。
- 开始日期不能产生逾期，日期和状态互不自动修改。
- 昨天开始、仍未开始且无到期日的任务持续留在当前关注；手动设为进行中始终进入当前关注，即使没有日期或排期在未来。
- 任务行状态下拉只含未开始、进行中、已完成，并显示边框、紧凑排列文字和箭头；标题下方只显示所属计划和未完成前置任务数量，悬停前置任务信息最多显示 10 个未完成前置任务名称及剩余数量；逾期在标题后同行显示独立警示图标和「已逾期」，不得显示为第四种状态或影响行操作对齐。
- 日期展示与设置合并为同一可点击入口：开始、到期日期按上下顺序显示，不加「开始」「到期」前缀，日期使用斜杠分隔，数字采用区别于正文的字体，保留已设置时分；只设置一项时仅显示该项，均未设置时显示「设置日期」。点击入口继续打开共享详情的日期设置，不创建或修改提醒。日历页面不改变。
- 今日完成可展开并重开任务；更早完成的任务不进入 Today。
- 任务按自身日期/状态分组，不要求其父任务也出现在 Today；本页面不承担任务树编辑。
- 当前关注固定显示且逾期置顶；待安排、今日完成分别读取 `today.show_unscheduled/show_completed`；稍后固定显示，默认折叠读取 `today.later_collapsed` 并继承旧明日折叠偏好。删除旧进行中/等待中显示开关。

## 5. 排序与呈现

### 5.1 默认排序

| 分组 | 默认排序 |
| --- | --- |
| 当前关注 | 逾期置顶 → 优先级降序 → 到期升序（空最后）→ 开始升序（空最后）→ 创建升序 |
| 待安排 | 优先级降序 → 创建倒序 |
| 今日完成 | 完成时间倒序 |
| 稍后 | 优先级降序 → 到期升序（空最后）→ 开始升序（空最后）→ 创建升序 |

完全相同的排序值用任务 ID 稳定兜底，刷新不随机跳动。

> **已确认（2026-10-26）Q-TODAY-01：** 页面头部是否显示「明日任务数」预告（如右上角徽标）？→ **当前默认处理：** 不显示，避免信息过载。明日数量仅在各分组徽标中可见。

> **已确认（2026-10-26）Q-TODAY-02：** 「明天」分组在非周五的周末日（周六/周日）是否会包含下周一的任务？→ **当前默认处理：** 不会。「明天」严格按自然日计算，即周日之后明天是周一，而非跳过周末。

### 5.2 自定义排序

设置 `tasks.default_sort` 仅调整当前关注，所有选项均保持逾期置顶；其余区域保持各自的固定排序规则。

| sort 值 | 排序依据 |
| --- | --- |
| `priority`（默认） | 按 §5.1 的日期类排序 |
| `created_desc` | created_at DESC |
| `due_date` | 到期升序（空最后）→ 优先级降序 → 开始升序 → 创建升序 |

### 5.3 显示上限

每个分组最多显示 200 条任务；超出时底部显示「显示更多 X 项」（可点击展开至上限 1000）。

> **已确认（2026-10-26）Q-TODAY-03：** 单个分组成员超过 200 时如何处理？→ **当前默认处理：** 显示「显示更多」按钮，点击后加载剩余项（每次追加 200），最多加载 1000 项。不采用虚拟列表（简化开发）。

## 6. 隐藏组的恢复

空区域不渲染头部及分隔线；刷新不擅自展开已有折叠区域。显示偏好开启时，新建独立任务成功后展开「待安排」；如果用户已隐藏该区域，则保持隐藏并按 SET-03 Q-SET-10 提供快捷恢复提示，不自动修改显示设置。

> **已确认（2026-10-26）Q-TODAY-04：** 如果某分组被折叠后清空，再次新建任务时该分组是否自动展开？→ **当前默认处理：** 是的，但该行为仅限于新建任务的操作触发的场景；刷新事件不触发自动展开。

## 11. 首个业务里程碑（2026-11-03 已确认）

- 范围：统一任务模型/校验、同一 DB 工作线程中的任务读写、真实今日列表、共享详情、自动保存与失败保护。
- 本轮只创建独立任务；不提供计划/父级选择、任务树移动、依赖编辑或系统提醒编辑。实体、外键和只读规则保留以供后续复用；完成已有提醒的任务仍须同事务暂停其提醒。
- 日期入口复用共享详情；首轮手输日期方案已由 §11.3 的日期时间选择组件替代。全局新建快捷键随对应模块接入。
- 今日显示偏好读取 ARCH-04 已登记键；设置入口由 D-TODAY-08 / SET-03 接入，排序/隐藏及保存反馈逻辑须测试覆盖。
- 文本编辑 500ms 防抖，字段失焦、关闭详情、换任务、切页、隐藏和退出前提交。新输入不能被旧保存回包或刷新覆盖；失败/非法输入保留草稿并阻止静默丢失。
- 保存成功才刷新数据库读模型；后台结果只经 Slint 事件循环更新。跨日本地日期每 30s 检查，隐藏驻留也会检查。
- UI 外观、中文输入法、焦点和鼠标/键盘操作由用户手工验收，自动检查只证明逻辑测试、编译及链接通过。

### 11.1 本轮代码落点与验收边界

- `fastnote-core::domain/derive/service`：实体、四态转换、八分组与排序、稳定错误码；`TaskClock` 注入 UTC 和本地日期转换。
- `fastnote-store::tasks`：与设置共用 `SqliteSettings` 的同一连接；即时事务、完整原实体比较、删除级联、完成同事务暂停提醒；无新增 schema 或数据文件。

- `fastnote-ui::today` 与 `ui/tasks/`：真实今日列表与 400px 共享抽屉；UI 只展示 core 的分组/逾期/等待标记。
- 当前交付不宣称计划板、日历、小记、提醒或日记业务已完成；其刷新事件已由统一命令层提供。行淡出/新建高亮等视觉微交互仍待后续细化，本轮先验收真实读写与保存保护。

### 11.2 任务行与日期入口修复（2026-11-03 用户反馈）

- 用户截图显示数量增加但标题不可见：任务行 `HorizontalLayout` 的 `center` 对齐禁止剩余宽度分配，导致无固有宽度的标题/点击区域缩为零。修正为 `stretch`，标题有明确最小/建议宽度，焦点/点击区域明确填满标题区域。

### 11.3 日期时间与行编辑调整（D-TODAY-02，2026-11-03 用户确认）

- 覆盖 §11.2 的临时日期输入方案：开始/到期使用日历与时分选择组件，24 小时制、分钟精度；不自动创建系统提醒。
- 排期保留 `start_date/due_date`，新增可空 `start_time/due_time`；旧数据不补写时间，仍按全天解释。开始/到期同日时校验时分顺序。
- 已超过到期日期时间的未完成任务进入逾期；当天尚未到时留在今日到期。其他七组仍按自然日去重，开始时间不切换状态。
- 日期类排序在同日期内比较时分，全天到期在该日具体时分之后、全天开始在具体时分之前；无日期仍最后。
- core 在完整候选集上给出下次到期边界；app 每 30s 检查该边界、本地跨日和时间回拨，隐藏驻留同样刷新，不受折叠/分页遮蔽。
- 行右侧依次为状态下拉、设置日期、优先级、删除；详情不重复状态/优先级编辑。外部首次点击只触发保存关闭，失败保留详情，不穿透执行底层操作。

### 11.5 日期摘要与状态底色（D-TODAY-04，2026-11-03 用户要求）

- 任务行的日期摘要移除「开始」「到期」前缀，两端日期用箭头连接；只显示已存在的日期及分钟，不制造默认日期或补写全天时分。
