## 1. 目的与范围

定义任务间的依赖（前置/后置）关系管理：添加、移除、可视化和冲突处理。确保用户能够明确表达任务的先后顺序，并在依赖阻塞时获得适当的提示。

**范围内**: 依赖的 CRUD、选择器、可视化标记、阻塞提示、循环检测。
**范围外**: 自动排期（v1 无）、跨项目依赖推荐（AI feature）。

## 3. 依赖界面

### 3.1 在任务详情面板中

```text
┌─────────────────────────────┐
│ ▶ 前置依赖                  │
│   • [设计评审]        ❌    │ ← 未完成 → danger icon
│   • [准备演示文稿]    ✓     │ ← 已完成 → success check
│                             │
│ [+ 添加前置]                 │
├─────────────────────────────┤
│ ▶ 后续依赖                  │
│   （只读列表，不可在此编辑）  │
│   • 开发实现              ✓ │
│   • 代码审查             ⚪ │
└─────────────────────────────┘
```

- 「前置」和「后续」各显示为可折叠区域。
- 每个依赖项左侧有状态图标（未完成/已完成）。
- 点击依赖项打开对应任务详情面板。

### 3.2 行内标记

在任务列表/树中，被前置阻塞的任务：
- 右侧显示 `⛓` 图标（黄色警告色）。
- Tooltip：「依赖 N 个未完成」。

## 4. 添加依赖

### 4.1 选择器行为

点击「+ 添加前置」→ 弹出下拉选择器：

| 功能 | 说明 |
| --- | --- |
| 候选任务列表 | 同计划内的所有未完成任务 |
| 搜索 | 输入框实时过滤（按标题匹配） |
| 多选 | 一次可选择多个作为前置 |

### 4.2 反向写入

> **已确认（2026-10-26）Q-PLAN-12：** 添加前置时是否同时在其「后续」列表中写入反向引用？→ **当前默认处理：** 不主动写入反向前置（successor 字段仅用于只读展示，数据层仍维护双向边但 UI 只显示 forward）。

## 5. 冲突与验证

### 5.1 循环检测

添加依赖后系统立即检测是否产生环路：

| 场景 | 行为 |
| --- | --- |
| 产生环路 | inline error「检测到循环依赖，无法添加」→ 操作回滚 |
| 部分成功 | 如果批量添加中有循环的那条失败，其余成功；Toast 告知 |

### 5.2 阻塞提示

当用户尝试开始或完成一个被阻塞的任务时：

| 条件 | 行为 |
| --- | --- |
| 有未完成的依赖 | Dialog「前置任务『X』尚未完成。仍要开始吗？」 |
| 用户选择继续 | 记录 override_reason → 允许继续 |
| 用户取消 | 保持原状 |

遵循 D-17：系统只提示，不锁定。

### 5.3 跨计划依赖

| 场景 | 行为 |
| --- | --- |
| 移动任务导致依赖跨计划 | Toast 警告「移动后将解除 N 条跨计划依赖」 |
| 用户确认移动 | 执行移动并自动解除跨计划依赖 |

---

## 6. 移除依赖

在任务详情面板的依赖列表中，每条依赖旁有「×」按钮 → 点击后立即删除该依赖关系。
