## 1. 目的与范围

定义设置中心的另外三个分组：全局快捷键管理（绑定表、修改流程、冲突提示）、任务偏好（默认排序、 Tomorrow 规则），以及关于页面（版本信息、许可证）。

**范围内**: 快捷键配置、任务默认排序、Tomorrow 受设置影响吗、快速添加隐藏行为、关于页面。
**范围外**: 通用设置（SET-02）、数据管理。

## 2. 全局快捷键配置

### 2.1 快捷键列表

| 功能 | 当前组合 | 操作 |
| --- | --- | --- |
| 唤起主窗口 | `Ctrl+Alt+Space` | 点击编辑 |
| 新建任务 | `Ctrl+Alt+N` | 点击编辑 |
| 新建小记 | `Ctrl+Alt+M` | 点击编辑 |

> 默认组合以 ARCH-04/06 为准（Q-SHELL-02，2026-11-02 已确认）。本轮只注册唤起、在通用页展示状态；编辑组合和新建两项随后续模块接入。

### 2.2 编辑流程

点击某条快捷键的「编辑」按钮 → 弹窗等待用户按下新组合 → 检测是否冲突 → 确认后替换旧值。

```text
┌───────────────────────────────────┐
│ 修改快捷键                        │
│                                   │
│ 功能: 唤起主窗口                  │
│                                   │
│ 当前: Ctrl + Alt + Space         │
│                                   │
│ 请输入新组合: [^ ]                │ ← 实时显示按键
│                                   │
│         [取消]    [确认]          │
└───────────────────────────────────┘
```

### 2.3 冲突处理

| 场景 | 行为 |
| --- | --- |
| 组合已被其他应用占用 | Dialog 告知被谁占用，不自动替换 |
| 与本应用另一功能重复 | Dialog 告知冲突关系 |
| 有效且无冲突 | 立即注册并保存 |

> **已确认（2026-10-26；2026-11-03 同步）Q-SET-06：** 明日预告不受 `tasks.default_sort` 影响，固定使用 ARCH-03 §9 的日期类默认排序；此配置仅影响逾期、今日到期、今日开始、进行中四组。

### 2.4 Week Start 跟随系统

> **已确认（2026-10-26）Q-SET-07：** 周起始日是否跟随操作系统设置？→ **当前默认处理：** 不跟随——固定为 Monday；用户在设置页可以手动改为 Sunday。

## 3. 任务偏好

### 3.1 默认排序

| 字段 | `tasks.default_sort` |
| --- | --- |
| 类型 | 下拉选择器 |
| 选项 | `priority`（默认）/ `due_date` / `created_desc` |

- 修改后刷新今日四个日期类分组，其他分组保持统一的固定排序。2026-11-03 用户要求接入设置入口及即时持久化，不再停留于仅读取偏好的阶段；快捷键编辑、关于等其他设置仍不属于本轮。

### 3.2 分组显示（D-TODAY-08，2026-11-03 用户要求）

设置入口沿用 ARCH-04 已登记的四个开关：`today.show_in_progress`、`today.show_waiting`、`today.show_unscheduled`、`today.show_completed`，默认均为 `true`。其他四组不新增隐藏设置；只隐藏已命中的组，不删除任务、不把任务转移到其他组，不重置已保留的分页或折叠状态。明日默认折叠配置继续读取，本轮不增加其编辑入口。

保存使用现有 SQLite 设置仓储和同一 DB 工作线程；成功后刷新今日列表，失败时保留已确认的值并给出中文错误，不假装成功。设置不新增「保存」按钮；保存期间禁用修改入口，成功/失败后恢复键盘焦点。页面提供既有设置分组导航，通用与外观、任务偏好为真实内容，其他分组明确保留未接入说明，不伪装成功能。

**Q-SET-10 已确认（2026-11-03 用户补充）：** 隐藏「未安排」后快速添加仍正常保存，不自动改变显示偏好；成功后给出带「撤销隐藏分组」快捷按钮的临时提示。点击该按钮通过同一设置保存流程开启 `today.show_unscheduled`，成功后展开并定位「未安排」，使该组可见；失败保持隐藏并提示。该操作幂等，不删除新任务，也不恢复其他分组的隐藏状态。带操作提示沿用 SHELL-02 的 6 秒停留及悬停暂停规则。

> **已确认（2026-10-26）Q-SET-08：** 同一快捷键组合是否可以交换使用场景（如 F 键在两个功能间互换）？→ **当前默认处理：** 不支持；每个组合只能绑定一个功能。避免多义性。

## 4. 快速添加默认行为

### 4.1 未安排任务的快速添加

当用户在快速添加输入框中创建一个没有指定日期的任务时：

| 场景 | 行为 |
| --- | --- |
| 今天 | 放入「未安排」组 |
| 明天 | 如果 due_date 为空但标题包含明天相关关键词 → 自动标记为明天（未来功能，v1 不做） |

> **已确认（2026-10-26）Q-SET-09：** 快速添加时未指定日期（即 unscheduled task）的行为是否需要特殊处理？→ **当前默认处理：** 首次出现在 Today 页的「未安排」组；下次再创建也如此，不隐藏该分组（除非全部为空则自动折叠）。

2026-11-03 Q-SET-10 补充覆盖可见性描述：新增任务始终归入「未安排」，是否显示由用户偏好决定；仅在用户点击提示中的快捷按钮后恢复显示。分组为空时仍不显示空组。
