## 1. 目的与使用方式

集中登记第一版的风险、技术不确定性与需要产品确认的设计选择。每条问题必须给出**当前默认处理**，确保开发不被阻塞；问题关闭后，在「结论」列记录日期与决定，并同步相关文档。

**优先级定义**

| 级别 | 含义 | 处理时限 |
| --- | --- | --- |
| P0 | 可能导致数据丢失、无法发布或核心入口不可用 | 开发前必须解决或降级 |
| P1 | 影响主要功能或平台可用性 | 第一个里程碑前解决 |
| P2 | 体验/范围问题，有可行默认 | 评审确认即可 |

## 5. 关键假设

| 编号 | 假设 | 若不成立的影响 |
| --- | --- | --- |
| A-01 | 单用户、单设备、纯本地使用，无并发写入 | 多实例/同步需重新设计 |
| A-02 | 用户界面第一版仅简体中文 | 需引入 i18n 与文案资源 |
| A-03 | 任务排期为本地日期与可空时分（D-TODAY-02）；提醒保持独立，二者按设备当前时区的墙上时间解释 | 固定绝对时区的任务需另行扩展模型 |
| A-04 | 数据规模 ≤1 万任务、5 千小记、3 千日记 | 查询/渲染策略需调整 |
| A-05 | 应用按用户安装，不需要管理员权限 | 安装/自启路径需调整 |
| A-06 | 用户接受「无云同步」，数据靠手动备份 | 需同步/账号体系 |
| A-07 | Slint 能覆盖主要交互（文本、列表、弹层、自定义绘制） | 需混合原生控件或更换 UI 方案 |
| A-08 | 第一版不接入任何网络，Agent 不实现 | 需安全/授权/审计设计 |

## 6. 已知限制（需在发布说明中告知）

1. **Wayland**：悬浮球位置与置顶由合成器决定；全局快捷键不可用（D-22）；建议使用状态栏模式。
2. **Linux 托盘**：GNOME 默认需安装 AppIndicator 扩展，否则托盘图标不可见。
3. **长文本**：小记 20,000 字符、日记 50,000 字符为上限；超出会提示。
4. **无搜索/筛选**：第一版只能通过日期与列表浏览；搜索为后续能力。
5. **无回收站**：删除不可恢复，依赖备份。
6. **归档隐藏**：归档计划的任务不再出现在今日/日历，可在计划板「已归档」查看。
7. **系统提醒运行边界**：完全退出后不提醒；恢复运行时仅汇总最近 24 小时错过项。权限、系统勿扰或 Linux 无通知服务可能阻止呈现，应用需显式提示与降级；不保证用户已经看见。
8. **无自动更新**：需手动下载安装包升级。
9. **无加密**：数据库与备份均为明文 SQLite 文件，依赖操作系统账户权限保护。

## 7. 问题关闭流程

1. 提出：在对应模块文档写 `Q-xx` 并登记本表，附「当前默认处理」。
2. 评估：产品/技术负责人确认影响面（数据模型、UI、平台、测试）。
3. 决策：更新本表「状态/结论」，同步修改受影响的 spec 与验收标准。
4. 验证：相关 AC 或 Spike 通过后，状态改为「已关闭」，记录日期。
5. 禁止：未登记的隐性决策；代码与文档不一致时以 spec 为准并回写。
