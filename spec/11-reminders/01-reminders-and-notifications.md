## 1. 范围与确认状态

### 1.1 用户已确认（2026-10-25）

- 第一版支持系统通知；任务（todo，指所有未完成的普通任务）和小记可以设置提醒时间。
- 支持单次、每天、每周重复；第一版不支持工作日、每月、复杂间隔、多时间点或多星期选择。
- 仅应用运行期间调度，主窗口隐藏但悬浮球/托盘驻留属于运行；完全退出后不提醒，不安装额外后台服务、不注册退出后系统计划。
- 启动/唤醒汇总补发最近 24 小时内错过的提醒；更早记录为已错过，不补发。
- Today 独立，日历月/周可点击日期查看详情；提醒不创建独立日视图、不引入小时网格。

### 1.2 研发默认（不是额外的用户确认）

一实体一条规则；每周为单个 ISO 星期；完成/归档暂停，重开不自动恢复；小记转任务不复制规则；设备本地墙上时间语义；默认通知不泄露正文。以下条款是可实施基线，变更必须同步领域、存储和测试。

## 2. 需求与边界

| 编号 | 需求 | 落点 |
| --- | --- | --- |
| REM-001 | 任务与小记独立设置时间 | §3、§4 |
| REM-002 | 单次/每天/每周 | §4、§5 |
| REM-003 | 运行期系统通知与权限降级 | §6、§7 |
| REM-004 | 最近 24 小时错过项汇总 | §5.3 |

| REM-006 | 备份/导入安全与不重放 | §9 |

提醒与排期分离：任务 `start_date`/`due_date` 仍为 date-only，不依据提醒改期、不因改期修改提醒、不因逾期自动创建通知。只有提醒而无排期的任务仍属 Today 未安排。小记不因此进入 Today 或日历。阶段、计划、日记不支持规则；重复提醒不等于重复任务，不会重新打开已完成任务。

## 3. UI 与交互

### 3.1 设置入口

- 任务统一详情抽屉在日期区下显示「提醒」行。未设置为「设置提醒」；设置后显示下一次本地日期时间和重复标签；暂停、结束、投递失败用文字标注，不仅靠图标。
- 小记编辑器工具条显示铃铛，列表显示提醒标记。无需转成任务即可设置。快速捕获仍只录正文，保存取得 ID 后可进入编辑器设置。
- 新建任务先落库取得 ID，才能写规则；正文保存失败不继续创建提醒。两次命令间失败保留已创建实体，并明确「内容已保存，提醒未设置」，不伪装为原子创建。
- 弹层宽 360px（不足则适应可用宽度），标题「设置提醒」，单选「单次 / 每天 / 每周」。单次显示日期和时间；每天仅时间；每周显示星期一至星期日单选和时间。统一 24 小时制，分钟步进 1，支持键盘输入。
- 首次打开预填：单次今天、当前时刻向上取整到下一分钟再加 30 分钟（跨日随日期进位）；每天预填同一时分；每周预填该日期星期与时分。这些只是草稿，确认后才写入。
- 日期/时分输入错误就近显示；新建/修改单次时间必须严格晚于提交时刻，避免刚保存即过期。每天/每周选过去时分表示下一天/周符合项，确认前显示「下次：…」。系统时间变化造成提交前过期则重新校验。
- 显式「确定 / 取消」提交组合规则，避免每个字段改动触发临时错误排程；这是对组合编辑的即时落库事务边界，不增加页面保存按钮。Esc 取消，IME 组合中先处理输入法。
- 已有规则提供「暂停 / 恢复 / 删除提醒」。删除不删任务/小记，无需破坏性内容确认，Toast「已删除提醒」。恢复过期单次需重新选未来时间，不能靠恢复立即补发。

### 3.2 权限与状态

首次主动确认规则时，按平台能力申请通知权限，不在冷启动弹权限框。权限拒绝仍保存规则，显示「提醒已保存，但系统通知未获允许」和设置入口；不谎称届时一定可见。不允许反复弹系统权限框。

设置「常规与待机」显示系统通知状态、说明、按需授权/打开系统设置、手动测试通知。权限状态是系统事实，不新增 `app_settings` 键；首次主动请求后系统决定后续是否可再请求。测试通知是平台动作，不创建持久规则或消耗 occurrence。

编辑器常驻说明：「仅 FastNote 运行时提醒；完全退出后暂停，到下次运行汇总最近 24 小时错过项。」主窗口显示/隐藏不改变提醒资格。提示明确区分“隐藏驻留”和“完全退出”。

### 3.3 通知内容与点击

- 默认标题「FastNote 提醒」，正文「有一项任务需要查看」或「有一条小记需要查看」；不包含任务标题、小记正文、计划名、路径等隐私内容，锁屏也不暴露正文。v1 不增加内容预览开关。
- 正常到时每 occurrence 最多提交一次；同一调度批次超过 3 项时改为汇总一条，避免同时轰炸，不以多个 OS 提交代替一条汇总。
- 单条点击：显示主窗口，任务打开统一详情，小记打开对应编辑器；无未保存内容时直接定位，否则先走统一保存/失败阻止跳转。已删除对象提示「内容已不存在」。
- 汇总点击：打开非模态「错过/到时提醒」会话列表（时间、类型、目标跳转，按时刻降序）；不是第六个导航页面，也不是独立日视图。可手动关闭，不标任务完成。列表由账本和现有 owner 投影重建；旧提醒被删除则不展示正文。
- 平台支持默认点击即可，不依赖“完成/稍后”系统 action；v1 不做贪睡或通知内改状态。Linux 无点击能力显示限制，用户可从应用内同一列表查看。
- 不抢焦点、不绕过系统勿扰、不强制声音；系统接收不代表已展示或已读。

## 4. 数据与服务契约

### 4.1 领域与字段

`ReminderId` 为 UUIDv7，`ReminderOwner = Task(TaskId) | Note(NoteId)`。

```rust
pub enum ReminderSchedule {
    Once { date: NaiveDate, time: NaiveTime },
    Daily { time: NaiveTime },
    Weekly { weekday: Weekday, time: NaiveTime },
}
pub struct UpsertReminder {
    pub owner: ReminderOwner,
    pub schedule: ReminderSchedule,
}
```

以 [ARCH-04 §4.8a](../00-architecture/04-storage-and-data.md) DDL 为唯一表定义：

- `reminders`：`id, task_id, note_id, schedule_kind, local_date, local_time, weekday, next_fire_at, last_handled_at, state, revision, created_at, updated_at`。
- `task_id`/`note_id` 恰一非空，各自部分唯一索引保证一个 owner 一条；级联删除。`once` 有 local_date 无 weekday；`daily` 两者为空；`weekly` 仅 weekday，ISO 1–7。严格校验合法日期、HH:MM，秒固定 0。
- `state=active|paused|finished`；只有 active 有下一次 UTC `next_fire_at`，暂停/结束置空。`last_handled_at` 是最近一次处理时刻，不是用户已读时间。
- `reminder_deliveries`：`id, reminder_id, rule_revision, scheduled_for, outcome, handled_at`，唯一 `(reminder_id,rule_revision,scheduled_for)`。outcome 为 claimed/submitted/failed/missed/suppressed；无用户已读状态，不存正文或 OS 授权令牌。
- 规则更新、暂停/恢复、owner 完成/归档使资格失效时递增 revision；元信息处理及 occurrence 前进不递增。修改规则不清历史账本，新 revision 使旧候选失效。

### 4.2 接口

| 层 | 接口 | 语义 |
| --- | --- | --- |
| Command | `UpsertReminder(UpsertReminder)` | 原子创建/替换并激活；若 owner 不可提醒则拒绝 |
| Command | `PauseReminder(ReminderId)` | active→paused，幂等 |
| Command | `ResumeReminder(ReminderId)` | paused→active，重新计算未来首次；过期单次拒绝，要求改时 |
| Command | `DeleteReminder(ReminderId)` | 删除规则及账本，owner 不变 |
| 内部 Command | `DispatchDueReminders { now: DateTime<Utc> }` | 单写 worker 批量领取、推进并输出投递意图；不供 UI/外部调用 |
| Query | `ReminderFor { owner: ReminderOwner }` | `Option<Reminder>`，包含下一次与最近投递状态 |
| Query | `NotificationStatus` | unknown/authorized/denied/unavailable + 原因/点击能力 |
| Event | `RemindersChanged { owners: Vec<ReminderOwner> }` | 调度器和对应详情/铃铛重查，不重建正文编辑器 |
| Event | `NotificationStateChanged` | 权限/能力变化后更新设置与编辑器状态 |

平台端口职责为探测权限、按需请求授权、提交即时通知、回传结果/点击。具体原生方法以 SPIKE-07 决定，不让 core 依赖 OS 或 Slint。平台调用不得在 DB 事务中执行。

### 4.3 owner 状态联动

| 事件 | 规则处理 |
| --- | --- |
| todo / in_progress / waiting 相互切换 | 保持，不因 waiting 或依赖阻塞禁用 |
| 完成任务 | 同事务 active→paused、revision+1；不自动结束后继，不自动重开重复任务 |
| 归档计划 | 同事务暂停该计划所有 active 任务提醒；提示影响数量 |
| 重开任务 / 取消归档 | 不自动恢复；保留用户暂停意图，用户手动恢复/编辑 |
| 移动到另一活动计划 | 规则保留，标题等通知目标重新读取 |
| 删除任务/计划/小记 | 外键级联清理规则与账本，投递候选失效 |
| 删除阶段且子任务移根 | 子任务仍存在，保留其规则 |
| 小记转任务 | 原小记及其提醒保留；新任务默认无提醒，转换结果明确说明不复制 |
| 解除小记-任务关联 | 双方独立规则不变 |

阶段、已完成任务、归档计划任务上新建/激活规则返回 `E_REMINDER_OWNER`；详情可只读显示已有暂停规则。

## 5. 时间与调度

### 5.1 设备本地墙上时间

单次使用所选本地日期时分，每天/每周使用设备当前本地时区。规则不固定“创建时的绝对时区”；设备换时区后以同一本地时间重新求下一次，UI 展示本地时区说明。UTC `next_fire_at` 只是缓存，不是规则事实。

- DST 不存在的本地时刻：移到当天首个有效时刻；例如 02:30 不存在且跳到 03:00，则该日 03:00，UI 预览调整说明。
- DST 重复时刻只采用较早一次；不能在回拨后的第二个相同本地时刻再次触发。
- app 层监听唤醒/时区/系统时钟变化并有 ≤30s 校验兜底；前台不依赖用户再次打开页面。
- 时区变化先处理变化前已到期项，再使旧候选失效并求新时区未来时刻；已处理的本地 occurrence 不因 UTC 变化重放。同一 revision 的旧 `next_fire_at` 与账本在重算前必须联合检查：本地日（daily）/本地周及 weekday（weekly）已处理则跳过；once 处理过即结束。不得单凭变后的 UTC 唯一键推断未处理。
- 时钟向前跳按恢复规则汇总；向后跳不回退已处理游标，不生成已处理日期的第二次。计算时注入 Clock/时区解析器，测试不能靠实际睡眠。

### 5.2 运行期调度与事务

1. 唯一主实例持有 `ReminderScheduler`（app 层），按最近 `next_fire_at` 设置计时器，并 ≤30s 校验时钟/唤醒。无需 1s 全表轮询，不新增 async runtime。
2. 内部命令交 DB worker，索引读取 `state=active AND next_fire_at<=now`；每批最多 200 条，持续排队但让出其它命令，避免 UI 写入饥饿。
3. `BEGIN IMMEDIATE` 重查 owner 资格、规则 revision；记录 claimed（唯一键冲突则不再领取），同事务推进 next_fire_at 或单次 finished，写 last_handled_at，提交。
4. app 层拿已提交意图，投递前经串行调度通道复核规则未修改/删除/暂停及 owner 资格；失效改 suppressed。资格变化取消尚未提交 OS 的意图。
5. 平台提交即时通知，不持有 DB 锁；回调再经 worker 记录 submitted/failed。系统投递成功不代表用户看到。不将网络/云作为兜底。
6. 操作系统已接受后发生的完成/删除竞态无法撤回已呈现内容；尽力按已知 OS ID 撤销，但不能承诺绝对撤回。点击时必须再次校验对象。

权限被拒/服务不可用/提交失败均不无限重试，不以重新开权限重放旧 occurrence；记录 failed，主窗口可见显示非打断提醒，隐藏时保留应用内待查看列表与通知状态警示，下次打开可查看。重复规则继续推进未来 occurrence；失败不删除规则。应用内降级不能被标为系统已送达。

### 5.3 启动、唤醒与错过窗口

- 基于持久 `next_fire_at` 找未处理 occurrence，而非仅依据上次退出时刻；强杀也不会跳过整个检查。
- 以本轮采样 `now` 固定窗口 `[now-24h, now]`（UTC 实际经过时长，不是“昨天自然日”）。窗口内未处理项汇总一条系统通知；更早项 missed，不向 OS 提交。正常稳定运行到时使用 §5.2，无需等恢复流程。
- 重复规则长时间未运行时，不枚举数年明细：窗口外按规则计算直接推进到窗口边界，仅留一个代表性 missed 记录与时间范围日志（无正文），窗口内最多 daily 2 次/weekly 1 次（含边界），逐 occurrence 去重；UI 计数按窗口内实际 occurrence，不将压缩的旧记录解释成精确总数。
- 同一规则窗口内多次可在汇总列表合并成一行并显示次数和最近时刻；通知显示「有 N 项错过的提醒」，N 为不同 owner 数，避免歧义。
- 用唯一键先领取所有参与项后提交一次汇总；失败不拆分为多条重试。关机/应用不运行期间不声称“准点通知”。

### 5.4 幂等与崩溃保证

只提供本地有界去重、best effort，不承诺 OS exactly-once：

- 领取事务前崩溃：游标不前进，下次正常补发检查可处理。
- 领取事务提交后、OS 调用前崩溃：重启把遗留 claimed 视为不确定失败，记录 failed，不自动重投，避免潜在重复；应用内显示“可能未送达”。
- OS 接收后、结果落库前崩溃：同样不重投，不把 claimed 判为成功。
- 编辑/删除使候选 revision 失效；投递前最后一次复核之后仍有极小 OS 竞态窗口，必须保留以上边界说明。
- 长期账本按 handled_at 清理超过 90 天记录，但保留当前 revision 最近一个已处理 occurrence 及必要本地游标依据，不能因清理重新通知旧日期。ID/owner 删除级联不受保留期限制。

## 6. 三平台集成与授权

详见 [ARCH-06 §9.3](../00-architecture/06-platform-integration.md)，SPIKE-07 是第一版发布门禁而非范围外候选。

| 平台 | 方向 | 必测 |
| --- | --- | --- |
| Windows | 原生 Toast，稳定 AppUserModelID/安装激活身份 | per-user MSI、通知关闭/恢复、隐藏驻留、点击回调 |
| macOS | UserNotifications，即时本地通知 | 签名 bundle、授权拒绝/重开、LSUIElement 无 Dock、点击 |
| Linux | Freedesktop Notifications、会话 D-Bus | GNOME/KDE、X11/Wayland、无服务、actions 缺失、会话重连 |

不因 Wayland 全局快捷键不支持而禁用通知。无需管理员权限。通知服务能力不可用必须明确提示，不静默吞掉。OS 专注/勿扰可能接收但不展示，应用不能准确判定已展示或已读。

## 7. 错误、隐私与性能

| 错误码 | 含义 | 处理 |
| --- | --- | --- |
| `E_REMINDER_INVALID` | 时间/重复组合非法或单次不在未来 | 就近校验，保留草稿 |
| `E_REMINDER_OWNER` | 阶段/完成/归档对象不可激活 | 说明原因，不改原规则 |
| `E_NOTIFICATION_DENIED` | 授权拒绝 | 保留规则，状态警示与系统设置入口 |
| `E_NOTIFICATION_UNAVAILABLE` | 系统服务缺失 | 应用内降级，禁止假成功 |
| `E_NOTIFICATION_FAILED` | 即时提交失败/遗留 claimed 不确定 | 账本 failed，应用内可查看，不无限重试 |

日志只记录 ID、规则类型、时间、状态、错误码，不记录任务标题/小记正文。数据库与备份仍未加密，依赖账户权限。系统 payload 不含正文；目标 ID 仅用于应用内定位，不提供任意 URI/命令执行能力。

设计上限为任务与小记总量（每 owner 一条）。索引查 due，不周期全表扫描；常驻空闲 CPU<0.5%、RSS≤80MB 沿用架构门限。正常运行、无阻塞/休眠/系统抑制时，从计划时刻到 OS 提交 p95≤5s；此指标不是实际可见时间承诺。唤醒后 DB 可用起 5s 内开始汇总处理，批量完成允许随数量增加且 UI 不阻塞。每批≤200，旧历史计算需跳跃而非逐日扫描。

## 8. 事件一致性

任务完成/计划归档事务同时更新其提醒，不等待 UI 通知后再暂停。`RemindersChanged` 仅重查受影响 owner 与调度缓存；通知权限变化走 `NotificationStateChanged`。所有页面显示的下一次时间/暂停/失败状态由同一规则和账本派生，UI 不另行排程。

停止调度、关库、恢复替换必须使在途回调带 generation；旧代回调不得写新库或按同 ID 操作新规则。完全退出先停止领取、收敛回调再关库，不能为通知无限延长退出。

## 9. 迁移、备份与导入

- schema=2：保留 v1 初始化，新增 `m0002_reminders.sql` 创建两表/索引；v1 升级后无提醒。完整 `.fnsbackup` 含规则与账本，计数含两表，旧备份缺省 0。
- 新 JSON `format_version=2`、`schema_version=2`；仍读 v1 原五集合（reminders 为空），v2 新增 reminders 集合。仅导出规则字段 `id,task_id,note_id,schedule_kind,local_date,local_time,weekday,state,created_at,updated_at`，不导出 `next_fire_at,last_handled_at,revision` 或投递账本。
- 合并生成新提醒 ID，重映射任务/小记 owner；替换保留 ID。验证 owner、唯一性、类型和时分，任何失败回滚整体。
- 恢复/导入与调度互斥，替换前暂停 dispatcher、提升 generation；失败回滚后重载原库。仅导出/在线备份本身不改变活跃调度。
- 成功后**重建当前时刻基线，不重放历史**：原 paused/finished 不复活；过去单次 finished；未来单次和重复仅原 active 且 owner 允许时激活，重复求严格未来下一次；完成/归档 owner 保持 paused。合并只重基线导入项，现有规则与账本保持不变。
- 恢复保留账本供审计但不重投，旧库 next_fire_at 作为缓存失效；恢复后的当前 revision 提高以使旧在途候选失效。导入 revision=1、账本从空开始。
- 正常启动/唤醒的 24h 补发不用于恢复/导入，这是防止旧备份消息轰炸的明确例外。

## 11. 决策记录与评审点

- D-REM-01：规则与排期分离，避免提醒隐式修改日历安排。
- D-REM-02：运行期调度与 24h 汇总为用户确认；不承诺完全退出后提醒。
- D-REM-03：一实体一规则、简单每周、完成/归档暂停、小记转换不复制是实现默认，不扩大为完整重复任务系统。
- D-REM-04：先领取再外部提交，接受极小漏通知窗口以避免崩溃后重复轰炸；状态必须诚实显示不确定失败。
- D-REM-05：默认不露正文，权限按需申请，系统失败显式降级；安装包能力以 SPIKE-07 为发布门禁。
