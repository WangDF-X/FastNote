## 1. 目的与范围

定义 FastNote 第一版的技术选型、运行时模型、性能预算、构建发布方式与编码约定，作为所有模块实现的技术基线。

**范围内**：语言/框架/关键依赖、线程模型、启动与退出流程、资源预算、目录结构、发布目标。
**范围外**：具体 Slint 组件实现（后续详尽级文档）、CI 流水线脚本、商店发布材料。

## 2. 技术选型

### 2.1 基线

| 项 | 选型 | 说明 |
| --- | --- | --- |
| 语言 | Rust stable，Edition 2021，MSRV 1.92 | Slint 1.18.1 的最低 Rust 版本为 1.92；当前开发环境为 Rust 1.99.1。 |
| UI | Slint 1.x 最新稳定版 | 声明式 UI、编译期检查、原生渲染、内存占用低。 |
| 存储 | SQLite 3（`rusqlite`，`bundled` + `backup`） | 本地单文件、WAL、事务、在线备份。 |
| 平台集成 | `winit` 原生窗口 + `tray-icon` / `muda` / `global-hotkey` / `auto-launch` / `single-instance` | 与 Slint 的 winit 后端同源，避免引入第二套窗口系统。 |
| 并发 | `std::thread` + `crossbeam-channel` | 不引入 async runtime（Tokio 等），降低常驻内存与复杂度。 |

> **设计决策 D-18：** 第一版不引入异步运行时。应用只有「UI 线程 + DB 工作线程 + 少量短生命周期后台线程」，用通道通信即可满足需求；async 生态会显著增加二进制体积和内存基线。

### 2.2 关键依赖

| 依赖 | 用途 | 约束 |
| --- | --- | --- |
| `slint` / `slint-build` | UI 与构建 | 仅启用 `backend-winit`、`renderer-femtovg`；不使用 Qt 后端。 |
| `rusqlite` | 数据访问 | `bundled` 编入 SQLite，避免用户环境缺库；`backup` 用于在线备份。 |
| `chrono` | 日期时间 | 日期用 `NaiveDate`，时刻用 `DateTime<Utc>`。 |
| `uuid` (v7) | 实体 ID | 时间有序、字符串存储，便于调试与合并。 |
| `serde` / `serde_json` | 导入导出、配置 JSON 值 | 仅用于文件边界，不作为主存储。 |
| `thiserror` | 领域错误 | 错误码稳定，供 UI 映射文案。 |
| `tracing` + `tracing-subscriber` + `tracing-appender` | 日志 | 按日滚动，单文件 ≤ 5MB，保留 7 天。 |
| `crossbeam-channel` | 线程通信 | 有界通道，命令队列容量 256。 |
| `tray-icon` / `muda` | 托盘图标与原生菜单 | Linux 需要 AppIndicator 运行时支持，见 ARCH-06。 |
| `global-hotkey` | 全局快捷键 | X11 可用；Wayland 走 Portal 或降级。 |
| `auto-launch` | 开机启动 | 三平台分别使用注册表 / LaunchAgent / autostart。 |
| `single-instance` | 单实例 | 第二次启动唤醒已运行实例。 |
| `directories` | 标准数据目录 | 按 OS 约定定位数据/日志/备份目录。 |
| `windows`（v1 Windows） / Slint/winit | 跟随系统主题 | 复用已有依赖读取注册表、监听 `WM_SETTINGCHANGE`；不新增 `dark-light`，检测失败回退浅色，并允许手动指定。 |
| `rfd` | 原生文件选择/保存对话框 | 备份、恢复、导入、导出。 |
| `arboard` | 剪贴板 | 复制小记、复制任务信息。 |
| `open` | 打开数据目录 | 调用系统文件管理器。 |

依赖新增规则：新增第三方依赖必须在 PR 中说明体积/内存影响；禁止引入网络、遥测、WebView 类依赖（与 D-06 冲突）。

### 2.3 不使用的技术

- **Electron / Tauri / WebView**：与轻量目标冲突。
- **Tokio / async-std**：无高并发 IO 需求。
- **ORM（Diesel/SeaORM）**：查询简单且需精细控制，使用手写 SQL + 仓储层。
- **前端状态框架**：Slint 模型 + 应用服务层足够。
- **云服务/SDK**：第一版纯本地。

## 3. 运行时模型

### 3.1 线程与职责

| 线程 | 职责 | 约束 |
| --- | --- | --- |
| UI 线程（main） | Slint 事件循环、窗口、视图模型、用户输入 | 禁止任何阻塞 IO / DB 调用超过 5ms；原生文件对话框等用户主动等待的模态交互除外。 |
| DB 工作线程 | 唯一写连接、事务、查询、迁移、备份 | 串行执行命令；崩溃不影响已提交事务。 |
| 平台事件线程 | 托盘/全局快捷键/主题变化回调 | 只投递事件到 UI 线程，不直接改状态。 |
| 短任务线程 | 导出、备份校验等长任务 | 带进度回调，可取消；同一时刻最多 1 个。 |

> 单写连接避免 SQLite 多写锁竞争；WAL 模式下读操作也走同一工作线程，换取实现简单与顺序一致。数据量（≤1 万任务）下查询延迟远低于一帧预算。

### 3.2 命令与查询流

```text
用户操作
  → Slint 回调（UI 线程）
  → UiCommand（校验轻量输入、置 loading）
  → crossbeam channel
  → DB 工作线程：AppService → Repository → 事务提交
  → DomainEvent + Result
  → invoke_from_event_loop
  → UI 线程：刷新受影响模型 / Toast / 错误提示
```

- 所有跨线程 UI 更新必须经 `slint::invoke_from_event_loop`。
- 命令/查询携带 `request_id`；页面查询及回收计时还需校验页面/主窗生命周期代次，丢弃过期响应，避免已卸载页面被迟到结果重新创建（D-RES-01）。
- 查询同样走工作线程；只查询当前需要的数据。可复用的低成本有效缓存可先展示；无缓存或已失效时给出轻量 loading，不为避免短暂加载而预建全部页面。
- DB 回包与必要平台事件由应用生命周期接收，不依赖主窗口组件存在。无可见页面时更新应用确认状态/失效标记，不创建页面、不投递页面重查；跨线程 UI 更新仍必须经事件循环。

### 3.3 启动流程

1. 解析启动参数与环境（`--hidden` 表示开机自启，仅显示常驻入口；`--restored` 表示刚从备份恢复，主窗首帧后展示一次性提示）。
2. 单实例检查；已有实例则发送「唤醒」消息并退出本进程。
3. 初始化日志、加载配置（设置表）。
4. 打开数据库（`PRAGMA` 配置）→ 执行迁移 → 完整性快检；失败进入「数据恢复」流程（见 09）。
5. 按配置建立常驻入口与轻量应用状态；不预建隐藏主窗口、业务页面模型或业务列表。必要数据库/日志/快捷键/提醒服务不属于页面缓存。
6. 注册全局快捷键、开机启动状态校验。
7. `--hidden` 或开机自启进入冷驻留，只显示入口；手动启动才按需创建主窗并加载今日任务。数据恢复/入口故障需要用户处理时，可按需打开错误界面，不把错误处理作为正常预热入口。
8. 日期/时区检查只让可见相关页面重查，隐藏/未创建页面仅记录失效；页面到期刷新定时器随页面挂载/卸载启停。DB 就绪后独立启动 `ReminderScheduler`，执行最近 24 小时错过提醒汇总，再按最近到期时刻调度（[REM-01](../11-reminders/01-reminders-and-notifications.md)）。`--hidden` 和主窗热缓存到期同样保持提醒；`--restored` 则先重建当前时刻基线，不补发备份历史。

**启动时间预算**：进程启动到入口可见 ≤ 600ms；到主窗口首帧 ≤ 1.0s（参考机见 §5.2）。数据库迁移/完整性检查超时 300ms 时先显示 UI，在后台完成。

### 3.4 退出流程

1. 捕获退出意图（托盘菜单、悬浮球菜单、设置页、系统会话结束）。
2. 冲刷未落盘的文本编辑（日记/小记立即提交）。
3. 停止提醒领取与定时器，收敛在途投递结果（不为通知无限等待）；注销全局快捷键、移除托盘图标/悬浮球窗口。完全退出后不触发提醒；关闭主窗口但驻留入口时继续调度。
4. 关闭数据库前执行 `PRAGMA wal_checkpoint(TRUNCATE)`（尽力而为）。
5. 正常退出码 0；系统会话结束允许 2s 超时强制退出。

完整退出立即取消主窗热缓存期限并清理资源，不等待两分钟。正常隐藏/回收先确认保存成功；保存失败保持编辑状态与草稿，不因缓存超时强制丢弃。

关闭主窗口 ≠ 退出应用：默认最小化到常驻入口（可在设置改为退出），见 02-desktop-entry/02。

### 3.5 崩溃与恢复

- 所有写操作单事务提交；WAL 保证崩溃后已提交数据不丢。
- panic hook 记录日志（不含正文）并尽力 checkpoint；release 使用 `panic = "abort"`。
- 启动时若数据库损坏：保留原文件副本 → 提示用户从备份恢复或新建空库，禁止静默重建。

## 4. 工程结构

```text
FastNote/
├── Cargo.toml                 # workspace
├── crates/
│   ├── fastnote-core/         # 领域实体、规则、服务、仓储 trait、错误、事件、DTO
│   ├── fastnote-store/        # SQLite 仓储实现、迁移、备份
│   ├── fastnote-platform/     # 托盘、悬浮球窗口、全局快捷键、自启、主题、单实例
│   ├── fastnote-ui/           # .slint 文件、视图模型、页面组件、文案映射
│   └── fastnote-app/          # 二进制入口、依赖装配、生命周期、命令总线、后台任务
├── ui/                        # 共享图片/图标资源（SVG/PNG）
├── spec/                      # 本设计文档
└── product.md
```

**依赖方向（单向）**

```text
fastnote-app → fastnote-ui → fastnote-core
      │              │              ↑
      ├──────→ fastnote-platform    │
      └──────→ fastnote-store ──────┘
```

- `fastnote-core` 不依赖任何 IO/UI/平台库。
- `fastnote-store` 实现 `fastnote-core` 定义的仓储 trait。
- `fastnote-ui` 只依赖 core 的 DTO/服务 trait，不直接访问 SQLite。
- `fastnote-platform` 不依赖 UI；通过回调/事件与 app 层交互。

## 5. 性能与资源预算

### 5.1 指标

| 指标 | 目标 | 测量方式 |
| --- | --- | --- |
| 入口可见（冷启动） | ≤ 600ms | 进程创建 → 悬浮球/托盘首次绘制 |
| 主窗口首帧（冷启动） | ≤ 1.0s | 进程创建 → 今日任务首帧 |
| 冷驻留内存 | ≤ 80MB RSS | Release，隐藏启动或热缓存已回收后，仅入口稳定空闲 10 分钟 |
| 热驻留内存 | ≤ 130MB RSS | Release，主窗隐藏后的最多 120 秒；重资源先回收，超预算可提前结束热缓存 |
| 主窗活动态内存 | ≤ 130MB RSS | Release，今日任务 + 1000 条任务；球模式主窗与球互斥，托盘按既有规则 |
| 空闲 CPU | < 0.5% | 无交互 5 分钟均值 |
| 列表滚动 | 60fps | 1000 条任务列表快速滚动 |
| DB 查询 p95 | < 10ms | 1 万任务、5 千小记、3 千日记 |
| 任务创建到界面可见 | < 100ms | 本地命令往返 |
| 安装包体积 | ≤ 25MB | Windows MSI / macOS DMG / AppImage |

资源验收使用同一参考机、隔离假数据和相同操作路径的 Release 构建。RSS（Resident Set Size，驻留集大小）在 Windows 以进程总工作集为主口径；记录原始字节，本文 MB 统一为 1,000,000 字节，不与 MiB 或任务管理器的不同列混比。同时记录专用提交内存及可获得的图形资源数据，Debug 数值不直接用于 Release 判定。80/130MB 是验收目标，不是当前实测结果；采样及回归方法统一见 [QA-03 §8](../10-quality/03-test-strategy.md)。

### 5.2 参考机

- Windows 11，4 核 2.0GHz，8GB RAM，SSD，集显。
- macOS 12+，Apple Silicon（M1）与 Intel 各一台。
- Ubuntu 22.04，4 核，8GB RAM，X11；Wayland 单独记录。

### 5.3 资源控制策略

- 悬浮球/托盘窗口无持续动画；仅 hover/press 时重绘，空闲不产生帧。
- 主窗口隐藏时停止页面定时器、查询和重绘；保留资源必须符合 §5.4 的白名单、容量及最长 120 秒期限，不再默认长期保留全部页面模型。
- 列表采用对应模块已确认的分页/虚拟化策略，并在查询层限制分配规模，不以全量读取后截断显示冒充按需加载。今日任务沿用每组初始 200、最多 1000 的分页及不采用虚拟列表的确认，不改变分组/完整计数/排序规则；内存峰值仍须满足预算。
- 图片/图标全部编译进二进制或按需加载小尺寸 SVG，不引入大图。
- 小记超过 20,000 字符（上限）、日记超过 20,000 字符时启用分段渲染/输入限流；日记上限 50,000（见 DIARY-01）。不因长文本阻塞 UI 线程。
- 日志异步写入，不阻塞 UI。

### 5.4 分级加载、热缓存与回收（D-RES-01，2026-11-04 已确认）

低内存常驻优先，允许冷热重开出现短暂加载。此策略管理运行时对象、数据与图形资源，不要求把 Rust 模块拆成动态库/独立进程，也不新增缓存时长设置键。

| 状态 | 允许持有/工作 | 不允许 |
| --- | --- | --- |
| 冷驻留 | 入口、确认配置、轻量路由/会话、必要 DB/日志/快捷键/提醒服务 | 主窗及业务页面实例、业务列表/正文缓存、页面轮询或绘制 |
| 主窗活动 | 按需创建唯一主窗，只加载当前页面/详情需要的数据 | 预载未进入模块、缓存全部历史访问页面、无上限全量列表 |
| 热驻留 | 主窗外壳与最近页面可回收的低成本资源，最多 120 秒 | 保留所有页面/大模型、隐藏刷新、为交互/后台事件续期 |

**资源分类与白名单：**

- 必要后台服务常驻，不按“使用少”回收；主窗卸载不能使 DB 回包无人处理、全局唤起失效或提醒暂停。
- 路由、日期、实体 ID、滚动锚点、折叠/分页等轻量会话与固定长度选项模型可复用。缓存需要明确的对象白名单、数量/容量边界和失效条件；不建立遍历过所有实体/页面的无界字典，不添加使用频率统计线程或遥测。
- 常用不等于低成本：大量任务行、完整计划树、已保存的长正文、大图片及昂贵绘图资源在离开页面/隐藏主窗后优先释放，不能仅因属于“今日任务”而永久缓存。小记/日记正文只为当前编辑及必要草稿保护持有。
- 主窗外壳和数据模型、原生窗口和图形上下文分别管理。大图形资源可先于外壳回收；到期必须解除主窗/页面/缓存的持有，验证原生窗口及图形资源确实释放。Slint/Windows 的 `hide()` 或重复设置不可见不作为销毁证明，所需能力以当前后端验证为准。
- 热驻留上限先沿用 130MB；超预算或收到系统内存压力时优先驱逐重缓存，必要时立即结束热缓存。更细的每对象容量由实现时的 Release 量测收紧并留档，不得未经确认放宽全局目标。

**两分钟期限：**

1. 从未落盘编辑已提交、主窗实际隐藏成功的时刻开始单调计时；保存等待时间不计入，隐藏失败不进入热驻留。
2. 两分钟内重开取消该次回收；再次真正隐藏建立新的 120 秒期限。已提前回收则按冷重开处理，不恢复被驱逐的大模型。
3. 球的拖动/悬停、入口菜单、主题/设置变更、后台通知/DB 回包不重置期限。普通托盘模式仅任务栏最小化仍遵循平台行为，不误当作隐藏驻留。
4. 到期在事件循环执行实际回收；睡眠时间计入期限，唤醒后的首次检查已过期就回收，不重新赠予两分钟。系统时间调整不延长期限，旧代计时回调不得销毁重开的主窗。
5. 完整退出不等待缓存期限；独立快速捕获窗的编辑/保存不被主窗回收影响，正在使用捕获窗不属于“仅入口”的量测场景。

### 5.5 缓存有效性与安全边界

- 命令提交后，可见相关页面按刷新矩阵查询；隐藏、未挂载或已卸载页面只标记范围/代次失效，不补建模型。重开仅加载当前路由所需数据，校验本地日期、时区、确认设置和数据变更，不能把失效缓存当作可编辑确认值。
- 页面卸载使其查询/订阅与代次失效；迟到读结果不得重建隐藏页面。写命令的成功/失败仍由常驻应用层处理，不因 UI 已卸载丢失结果或重复提交。
- 正常离开/隐藏先冲刷编辑；未保存/保存失败的草稿不能被超时/内存压力驱逐，默认阻止隐藏/回收并显示错误，或由应用层保留完成恢复所需的最小草稿。不得把保护中的编辑状态伪报为已回收冷驻留。
- “页面状态保留”指轻量会话可恢复，不是完整列表/正文/组件必须永久存在。卸载不重置日期、ID、折叠/分页，也不删除或重分组数据库任务。

### 5.6 落地与验证状态

本次仅修订规格，D-RES-01 已确认但尚待代码实现及 L7 资源验收。当前启动预建主窗/今日模型、隐藏后持有业务模型及后端默认隐藏行为需要另行整改；现有格式/Clippy/测试/构建结果不证明分级资源要求已实现，也不能据此给出 Debug 与 Release 的内存差值。

后续大型业务模块扩展前应先建立按需资源生命周期与 Release 基线；新模块按上述所有权/回收契约装配，不把低内存治理留到功能全部完成后。本次不修改运行代码、不执行资源验收。

## 7. 编码约定

1. **错误**：`fastnote-core::AppError` 使用 `thiserror`；生产代码禁止 `unwrap()`，仅允许在测试与启动期不可恢复不变量使用 `expect("...")`。
2. **日期时间**：业务日期用 `NaiveDate`，任务排期可附分钟精度的本地 `NaiveTime`（D-TODAY-02）；审计时间戳统一 UTC。本地日期时间转换由应用注入的 `TaskClock` 统一提供，core 不读取系统时钟。
3. **ID**：UUID v7 小写字符串；所有实体主键由应用层生成，数据库不依赖自增。
4. **SQL**：全部参数化；迁移脚本只增不改；仓储层不得拼接用户输入。
5. **UI 文案**：中文文案集中常量管理，错误通过 `E_*` 码映射；禁止在 UI 拼接内部错误细节。
6. **日志**：`tracing`；禁止记录任务标题、描述、小记/日记正文；允许记录 ID、数量、耗时。
7. **可测试性**：领域规则纯函数化；仓储 trait 便于内存实现；时间通过 `Clock` trait 注入（便于测试跨日）。
8. **格式与静态检查**：`cargo fmt`、`cargo clippy -- -D warnings`、`cargo deny` 检查许可证与漏洞。
9. **提交**：小而聚焦；涉及 schema/规则的提交必须同步 spec 文档。

## 8. 技术风险与预研项

| 编号 | 风险 | 影响 | 应对 |
| --- | --- | --- | --- |
| SPIKE-01 | Slint 透明/无边框/置顶悬浮球窗口在三平台表现不一 | 入口形态不可用 | 第 1 周做三平台最小验证；必要时用 `winit` 原生窗口承载 Slint 渲染并设置窗口属性 |
| SPIKE-02 | Slint 中文输入法（IME）候选框定位与组合输入 | 日记/小记不可用 | 尽早在三平台实测；记录规避方案（独立输入区域、升级 Slint） |
| SPIKE-03 | Linux 托盘（GNOME 默认无 AppIndicator） | 状态栏模式不可见 | 文档提示安装扩展；悬浮球作为默认；检测失败时提示切换 |
| SPIKE-04 | Wayland 全局快捷键/窗口定位限制 | 快捷键失效、球无法固定位置 | 走 XDG Portal GlobalShortcuts；失败时禁用并说明；建议 Wayland 用户用托盘模式 |
| SPIKE-05 | 长文本编辑性能（>2 万字符） | 输入卡顿 | 限制长度、分段渲染、降级为只读预览 |
| SPIKE-06 | 三平台代码签名/公证成本 | 无法分发 | 早期申请证书；Linux 提供免签 AppImage |

> **已确认（2026-10-26）Q-01：** Slint 稳定版对 `no-frame`、`always-on-top`、透明背景的支持程度需以实际版本文档与 Spike 结果为准；本 spec 只约定产品行为，不锁定 API。当前默认：优先 Slint 原生属性，不足时通过 winit 原生窗口句柄设置。

## 9. 验收标准

| 编号 | 验收标准 |
| --- | --- |
| AC-ARCH-01 | 三平台均可完成安装、启动、显示常驻入口、打开主界面。 |
| AC-ARCH-02 | 在同一参考机以 Release 和 QA-03 §8 的统一口径达到 §5.1 指标；Debug 占用、编译通过或工作集瞬时下降不替代验收。 |
| AC-ARCH-03 | 无交互 5 分钟 CPU 均值 < 0.5%，无持续重绘。 |
| AC-ARCH-04 | 所有数据库写入均在事务内，强制结束进程后重启无部分写入。 |
| AC-ARCH-05 | 从上一版本数据库升级后，计划/任务/小记/日记/设置数量与内容一致。 |
| AC-ARCH-06 | 生产代码无 `unwrap()`（CI 静态检查），无网络依赖。 |
| AC-ARCH-07 | 日志不包含任何任务/日记正文内容。 |
| AC-ARCH-08 | 单实例生效：重复启动不产生第二个进程，原窗口被唤醒。 |
| AC-ARCH-25 | 正常 `--hidden` 启动处于冷驻留，不创建主窗/业务页、不发起页面列表/正文查询；必要后台服务可用。 |
| AC-ARCH-26 | 首次打开主窗/进入模块才加载当前所需组件与数据，访问多个模块不无限累积页面/正文缓存。 |
| AC-ARCH-27 | 热缓存从保存完成且隐藏成功起最多 120 秒；重开取消、再隐藏重新计时，球/菜单/后台事件不续期，睡眠/旧回调不造成延长或误销毁。 |
| AC-ARCH-28 | 重资源优先释放；到期或超预算提前回收主窗及缓存持有，原生/图形资源释放有证据，不以 `hide()` 代替；轻量会话重开可恢复。 |
| AC-ARCH-29 | Release 冷驻留 ≤80MB、热驻留/主窗活动态 ≤130MB；重复冷热开关后冷态回到稳定范围，专用提交内存无持续累积。 |
| AC-ARCH-30 | 保存失败/在途保存的草稿不被超时或内存压力丢弃；已卸载页面的旧查询不补建模型、旧回收回调不销毁新主窗。 |
| AC-ARCH-31 | 隐藏页面无周期查询/刷新/绘制；重开校验跨日/时区/设置/数据失效，只刷新当前需要范围，提醒与必要 DB 回包不依赖主窗存在。 |
| AC-ARCH-32 | 缓存状态机/代次/计时/草稿保护有纯逻辑测试；按 QA-03 §8 留存 Release 冷热驻留及多轮回收证据，不把本次文档修订标为资源验收通过。 |
